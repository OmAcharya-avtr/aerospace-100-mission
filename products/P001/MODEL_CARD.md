# Model Card — BeamTwin Fade-Probability Surrogate

**Model name:** `beamtwin.surrogate.FadeSurrogate`
**Version:** 0.1.0 · **Date:** 2026-08-06 · **Status:** TESTING
**Owner:** OPTIMA Organisation · **License:** AGPL-3.0-only

> **This model is not certified for operational flight use.**

---

## 1. Problem

Predict the **fade probability** of a free-space optical link — the
probability that instantaneous received optical power falls below the
receiver sensitivity — directly from link and channel parameters, without
running a Monte Carlo simulation.

Target variable: `log10(P_fade)`, floored at `log10(1e-4)`.
Regression, single scalar output plus an uncertainty estimate.

**Why a surrogate exists.** A closed-form solution is available for
*scintillation-only* fading (see §2) but not for the combined case where
pointing jitter and scintillation act together. The combined case requires
~1e5 Monte Carlo samples per query, which is too slow for interactive
parameter sweeps, optimisation loops, and design-space exploration.

## 2. Baseline (implemented first, per mission §11)

`beamtwin.stats.analytic_fade_probability_lognormal` — closed-form lognormal
fade probability via the Gaussian Q-function in the log-domain:

```
P_fade = Phi( (ln 10^(-M/10) + sigma_ln^2 / 2) / sigma_ln )
```

(Andrews & Phillips 2005, Ch. 11.) Exact when pointing jitter is zero and the
weak-fluctuation regime holds. Validated against Monte Carlo in 5/5 cases
within the MC 95 % confidence interval (`validation/VALIDATION.md` §2).

**The baseline is the reference the ML model must beat or match.** It is not
a strawman — in its regime of validity it is essentially exact and the ML
model is decisively worse there (§6).

## 3. Architecture

- 5 × `sklearn.ensemble.GradientBoostingRegressor`, each `n_estimators=300`, `learning_rate=0.05`, `max_depth=3`, `subsample=0.8`.
- Each member is fitted on an independent **bootstrap resample** of the training set with its own `random_state` (`7 + member_index`).
- Prediction = ensemble mean of `log10 P_fade`; uncertainty = ensemble standard deviation.
- No feature scaling (tree models are scale-invariant).
- Model size on disk: ~2.5 MB (`models/surrogate.joblib`, committed).

**Features (5).** Chosen to be dimensionless or physically normalised so the
model generalises across link geometries:

| # | Feature | Units | Training range |
|---|---|---|---|
| 1 | `log10_range_m` | log10(m) | 3.0 … 4.301 (1–20 km) |
| 2 | `log10_cn2` | log10(m^−2/3) | −16.0 … −13.301 |
| 3 | `jitter_ratio` = σ_jitter / θ_divergence | — | 0.0 … 0.5 |
| 4 | `attenuation_db_per_km` | dB/km | 0.0 … 3.0 |
| 5 | `margin_db` (deterministic budget margin) | dB | −5.0 … 25.0 |

Queries outside these bounds set `extrapolating=True` on the prediction.

## 4. Dataset

See `DATASET_CARD.md`. 4000 scenarios generated by the twin's own seeded
Monte Carlo (50 000 samples each), master seed 42. Train/test split 80/20,
split seed 123 → 3200 train / 800 test.

**Test-split strategy:** a uniformly random split of independently drawn
scenarios. Because every scenario is an independent draw from the parameter
prior, a random split is a valid held-out estimate — there is no grouping,
time ordering, or near-duplicate structure to leak across the boundary. It
does *not* test generalisation beyond the training domain; that is measured
only by the extrapolation flag, not by a metric.

## 5. Training procedure

```bash
python scripts/generate_dataset.py    # 12.3 s, seed 42 -> data/surrogate_dataset.npz
python scripts/train_surrogate.py     #  5.8 s, split seed 123, model seed 7
```

Total **18.1 s** on 2 CPU cores — well inside the 3-minute budget. Fully
deterministic: identical commands reproduce identical models and metrics.
No hyperparameter search was performed; the values in §3 are defaults chosen
for a small tabular regression and were not tuned against the test set.

## 6. Metrics

Held-out test set (n = 800), error in `log10 P_fade`:

| Subset | n | MAE surrogate | MAE baseline | RMSE surrogate | RMSE baseline |
|---|---|---|---|---|---|
| All test | 800 | **0.270** | 0.404 | **0.377** | 0.843 |
| Low jitter (ratio < 0.05) | 80 | 0.348 | **0.005** | 0.485 | **0.012** |
| High jitter (ratio ≥ 0.05) | 720 | **0.261** | 0.448 | **0.363** | 0.889 |

An MAE of 0.270 in log10 means a typical prediction is off by a factor of
~1.9 in probability. This is coarse. It is useful for ranking designs and
for sweeps, and unsuitable for certifying an availability figure.

**Speed (measured, `validation/v3_performance.txt`):**

| Method | Cost per query | Relative |
|---|---|---|
| Surrogate (batched) | 7.60 µs | 1× |
| Monte Carlo, 1e5 samples | 6004 µs | 790× slower |

**Value proposition, stated exactly:** the surrogate is worth using *only*
when pointing jitter and scintillation combine — the regime where the
analytic baseline is scintillation-only and therefore structurally wrong —
and *only* when speed matters more than a factor-of-two accuracy. In the
scintillation-only limit the analytic baseline is exact and must be preferred.

## 7. Uncertainty output

Every prediction returns `probability`, `p_low`, `p_high` (±2 ensemble std in
log10 space), `log10_std`, and `extrapolating`.

**Calibration — measured, and poor:**

| Metric | Measured | Gaussian ideal |
|---|---|---|
| Coverage of ±1σ | 21.1 % | 68.3 % |
| Coverage of ±2σ | 39.9 % | 95.4 % |
| Mean σ vs mean abs error | 0.091 vs 0.270 | equal |
| Spearman corr(σ, abs error) | +0.388 | > 0 |

The band is **under-dispersed by roughly 3×**. Bootstrap resampling was
adopted because the naive ensemble was worse (21.6 % at ±2σ); the improvement
to 39.9 % is real but does not make the interval calibrated.

**Correct interpretation:** treat `log10_std` as a *relative confidence
ranking* — predictions with larger spread are less trustworthy — supported by
the positive rank correlation with actual error. **Do not treat `[p_low,
p_high]` as a 95 % interval.** Conformal or quantile calibration is deferred
to v0.2.

## 8. Failure cases (known, measured)

1. **Scintillation-only regime.** MAE 0.348 vs the baseline's 0.0049 — 71× worse. Use the baseline instead.
2. **Rare events.** Cannot predict below `P_FLOOR = 1e-4`; the training labels are floored there. A prediction of 1e-4 means "below 1e-4" and carries no resolution. Availability targets of 99.999 % are out of reach.
3. **High fade probability.** In `examples/fade_vs_range.py` at 15 km the surrogate predicts 0.668 vs Monte Carlo 0.944. Because training minimises error in log10 space, absolute probability error is largest where P is near 1.
4. **Extrapolation.** Outside the §3 bounds predictions are unvalidated; the `extrapolating` flag is set but no error bound is implied. Tree ensembles extrapolate flat, so out-of-domain predictions saturate silently.
5. **Fixed wavelength.** All training data is 1550 nm. The wavelength is not a feature. Predictions at other wavelengths are invalid even though the API accepts them.
6. **Inherited model-form error.** The surrogate learns the twin's Monte Carlo, so it inherits every assumption in `validation/VALIDATION.md` §6.5 (lognormal weak fluctuation, point receiver, no aperture averaging, no beam wander). It cannot be more correct than its teacher.

## 9. Reproducibility

```bash
git checkout <this commit>
python scripts/generate_dataset.py    # master seed 42, 4000 scenarios x 5e4 MC samples
python scripts/train_surrogate.py     # split seed 123, model random_state 7
python -m pytest tests/test_surrogate.py -q
```

Seeds: dataset 42, split 123, ensemble members 7–11 (bootstrap and fit share
the member seed). `models/surrogate.joblib` is committed; the dataset
(`data/surrogate_dataset.npz`, ~160 KB) regenerates deterministically.
Software: Python 3.11.15, numpy 2.4.4, scikit-learn (environment version),
Linux x86_64.

## 10. Compute used

Dataset generation 12.3 s + training 5.8 s = **18.1 s** on 2 CPU cores,
< 500 MB RAM. Total across all development retraining runs: under 5 minutes
of CPU time. No GPU.

## 11. Ethical and safety limits

- **This model is not certified for operational flight use.**
- Research and educational use only. Not flight-qualified, not certified, not approved for operational aerospace use.
- Must not be used to size link margins, set availability guarantees, or make go/no-go decisions for any real optical link, terrestrial or space.
- Trained purely on synthetic output of a simplified physics model; it has never seen a measurement from a real FSO link.
- The uncertainty output is not calibrated (§7) and must not be presented as a confidence interval to a decision-maker.
- No personal data is involved. No dual-use concern beyond that of FSO link engineering generally.
- Anyone using the outputs should read `validation/VALIDATION.md` §7 ("What was NOT validated") first.
