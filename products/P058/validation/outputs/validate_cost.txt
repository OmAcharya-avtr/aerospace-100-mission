2. The windowed KS implementation against SciPy
------------------------------------------------------------------------------
  The detector implements the two-sample KS statistic directly. SciPy's
  ks_2samp is the correctness reference (validate_known_answers.py s.3);
  here it is the cost reference.

  this package   median      43.2 us per evaluation (range 34.5 to 47.4)
  scipy ks_2samp median    1027.2 us per evaluation (range 997.0 to 1060.2)
  ratio          23.8x
  PASS  the direct implementation is cheaper than the SciPy call  [23.8x]
  FINDING  the direct KS statistic is about 24x cheaper per evaluation than scipy.stats.ks_2samp, which is why it exists; the two agree to machine precision on the statistic. SciPy additionally returns a p-value, which this package does not need and does not use.

3. The learned detector's online cost, and why the harness batches
------------------------------------------------------------------------------
  online, one forest call per sample : median     7574.2 us/sample (range 7337.6 to 7958.1)
  batch, whole stream at once        : median      6.802 us/sample (range 6.446 to 7.693)
  ratio                              : 1113x
  cheapest analytic detector         : median      0.352 us/sample
  online learned / cheapest analytic : 21538x

  Read that figure carefully. Most of the online cost is scikit-learn's
  fixed per-call overhead on a single row -- input validation, array
  wrapping, the Python call into the tree ensemble -- not the traversal
  of 100 shallow trees, which is a few microseconds of actual work. The
  batch column is the same trees doing the same arithmetic. So the honest
  claim is about this API in this environment, not about decision forests
  in general: a C or batched implementation would be far cheaper. What
  does transfer is the direction and the order of magnitude. A detector
  that needs a model call per telemetry sample is in a different cost
  class from a three-line recursion, and on a spacecraft processor that
  distinction decides whether it can run at all.
  PASS  the batch path is at least 100x cheaper per sample than the online path  [1113x]
  FINDING  the learned detector's online per-sample cost is about 21538x the cheapest analytic detector's with this scikit-learn API on this container, because it makes one single-row forest call per sample; the batch score path is about 1113x cheaper per sample and gives bit-identical results (tests/test_benchmark.py pins the identity). Most of the online figure is scikit-learn's fixed per-call overhead rather than tree traversal, so the magnitude is API-specific and only the order of magnitude and the direction should be carried elsewhere. A streaming deployment does not get the batch path.

4. The RandomForest n_jobs defect, re-measured for this product
------------------------------------------------------------------------------
  An earlier session in this portfolio recorded that n_jobs > 1 is
  5.7-8.9x SLOWER than n_jobs = 1 at single-row inference. The learned
  detector makes exactly that call once per sample, so the defect is
  re-measured here rather than taken on trust.

  n_jobs = 1: median    7363.2 us per single-row call (range 7336.4 to 7596.7)
  n_jobs = 2: median   33703.3 us per single-row call (range 31726.6 to 33744.4)
  ratio n_jobs=2 / n_jobs=1: 4.58x
  PASS  n_jobs > 1 is slower at single-row inference, as recorded  [4.58x slower]
  FINDING  RandomForestClassifier.predict_proba on a single row is 4.58x slower with n_jobs = 2 than with n_jobs = 1 on this container, reproducing the defect an earlier session recorded. This package sets n_jobs = 1 after fitting for that reason.
