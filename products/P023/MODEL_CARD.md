# Model card — `alloclab.ml.LearnedAllocator`

**This model is not certified for operational flight use.**

Version 0.1.0. Every number below comes from
[`validation/validate_ml_vs_qp.py`](validation/validate_ml_vs_qp.py); its raw
stdout is [`validation/ml_vs_qp_output.txt`](validation/ml_vs_qp_output.txt).

---

## 1. Problem

Given a desired body torque `tau` (3 vector, N·m) and a health mask saying
which of `m` effectors can still move, produce the effector command vector `u`
(m vector) that the bounded quadratic-programming allocator
`alloclab.allocation.qp_allocate` would produce. This is *surrogate modelling*:
the model learns to imitate a solver, not to model a physical system.

The motivation for trying is the standard one in control allocation — an exact
QP has to run every control cycle, and a fixed-cost function evaluation is
attractive if it is fast enough and accurate enough. Section 7 reports whether
that held.

## 2. Baseline

`alloclab.allocation.qp_allocate`, which solves

    min_u ||W_u (u - u_p)||^2 + gamma ||W_v (B u - tau)||^2,  u_min <= u <= u_max

by the BVLS bounded-variable least-squares active-set algorithm (Stark &
Parker 1995) on the stacked matrix `[sqrt(gamma) W_v B ; W_u]`. It terminates
finitely at the exact optimum. The baseline was implemented, tested and
validated (validation sections 1-4) **before** any model was trained, and the
model's training labels are its output.

Four other classical allocators are in the package and are also validated:
pseudo-inverse, weighted pseudo-inverse, redistributed pseudo-inverse, and
linear-programming allocation.

## 3. Architecture

Ensemble of 5 `sklearn.neural_network.MLPRegressor`s, hidden layers
`(64, 48)`, ReLU, Adam, `alpha=1e-4`, `max_iter=300`, `early_stopping=True`
with `n_iter_no_change=15` and `validation_fraction=0.1`. Member `k` uses
`random_state = 0 + k`.

- **Inputs** (11 features for `m = 8`): `tau / torque_scale` (3), where
  `torque_scale` is the largest commanded torque magnitude in the training set;
  then the health mask (m), 1.0 per effector that can still move. Features are
  standardised by a `StandardScaler` fitted on the training set. The health
  mask is an explicit input so that "this effector is failed" is representable
  rather than something the network must infer.
- **Outputs** (m): commands normalised to `[0, 1]` across each effector's own
  `[lower, upper]` span, mapped back on prediction.
- **Uncertainty**: the per-effector standard deviation across the 5 members,
  plus a scalar `confidence = exp(-mean_i std_i / reference_spread)` in
  `[0, 1]`, where `reference_spread` is the mean ensemble spread on the
  training set. Confidence 1 means the members agree as well as they did in
  training.

There is no PyTorch in the target environment and only two CPU cores, so a
deeper model, a convolutional or graph architecture over the effector geometry,
or a differentiable-optimisation layer that would enforce the box were all out
of scope. That is a constraint on this result, not evidence about what such
models would do.

## 4. Dataset

See [`DATASET_CARD.md`](DATASET_CARD.md). Fully synthetic, generated by
`alloclab.dataset.generate_dataset`, deterministic in an integer seed.

- Train: 4000 samples, seed 1234, attainable fraction 0.9550.
- Test: 2000 samples, seed 5678, attainable fraction 0.9575.

The two sets are drawn from the same generator with different seeds. There is
no natural grouping to split on — every sample is an independent draw — so the
split is by seed, and the test set is never touched during fitting. The 10%
`validation_fraction` scikit-learn holds out for early stopping comes from
inside the training set.

Effector configuration is fixed: the reference eight-thruster cluster
(`alloclab.dataset.reference_thruster_cluster`, `max_thrust=1.0 N`,
`arm=0.5 m`). The model is tied to it; see section 9.

## 5. Training procedure

```bash
python validation/validate_ml_vs_qp.py
```

Fixed seeds throughout: dataset 1234 / 5678, model `random_state=0` (members
0-4). No hyperparameter search was run — the architecture and the training size
were chosen once to fit the compute budget, and the first trained model is the
one reported.

## 6. Compute

2 x86-64 CPU cores, no GPU. Python 3.11.15, numpy 2.4.4, scipy 1.17.1,
scikit-learn 1.8.0.

| Step | Wall clock |
|---|---:|
| Training-set generation (4000 exact QP solves) | 4.10 s |
| Test-set generation (2000 exact QP solves) | 1.98 s |
| Fitting 5 MLPs | 115.22 s |
| **Total** | **121.29 s** |

Two of the five members hit `max_iter=300` and emit a scikit-learn
`ConvergenceWarning`; both warnings are in the raw output. Budget for this
product is 180 s of training, so the training size and network width were sized
to fit it.

## 7. Metrics — the learned model against the exact QP

Held-out 2000 samples. Allocation error is `||tau - B u||` in N·m; the effector
set's AMS boundary radius is 1.707107 N·m, so an error of 1e-2 N·m is 0.6% of
full authority.

| Allocator | Mean error | Median | p95 | Max | % inside actuator bounds |
|---|---:|---:|---:|---:|---:|
| Exact QP | 7.183888e-04 | 1.400865e-12 | 6.743076e-12 | 5.413941e-02 | **100.00** |
| Learned, raw output | 1.043167e-02 | 7.605578e-03 | 2.704358e-02 | 8.937423e-02 | **4.85** |
| Learned, clipped into the box | 1.538573e-02 | 8.987115e-03 | 4.674646e-02 | 3.361737e-01 | 100.00 |

On the 1915 samples the QP meets exactly, the QP's mean error is
1.618039e-12 N·m and the learned model's is 1.011498e-02 N·m — seven orders of
magnitude apart. The QP's non-zero mean over all 2000 comes from the 85 samples
whose command lies outside the attainable set, where no allocator can be exact.

**Constraint satisfaction, the finding:**

| | Learned (raw) | Exact QP |
|---|---:|---:|
| Samples violating at least one actuator bound | **1903 / 2000 (95.15%)** | 0 / 2000 |
| Largest violation | **0.3294 N** (32.9% of the 1 N thrust limit) | 0 |
| Mean violation over violating samples | 0.01762 N | — |

Per-effector largest violation [N]:
`[0.0796, 0.1971, 0.1983, 0.1600, 0.1765, 0.1592, 0.2273, 0.3294]`. Every one of
the eight thrusters is commanded out of range somewhere in the test set.
Nothing in a plain regression enforces the box; this does not shrink to zero
with more data, it is structural.

`predict(clip=True)` projects into the box and restores 100% compliance, at the
cost of a 47% larger mean error and a 3.8× larger worst case. The default is
`clip=False` so that the violation is visible rather than silently absorbed.

**Runtime:**

| Path | Per allocation | vs the exact QP |
|---|---:|---:|
| Exact QP, one command at a time | 696.3 µs | 1.00× |
| Learned, one command at a time | 1417.4 µs | **0.49×** |
| Learned, 2000 commands batched | 64.0 µs | 10.88× |

The expected speed-for-exactness trade only half materialised: **called one
command at a time, which is how a control loop calls an allocator, the model is
twice as slow as the exact QP.** Five scikit-learn `predict` calls plus feature
scaling cost more than one bounded least-squares solve on a 3×8 problem. The
10.9× advantage requires batching 2000 commands, which a real-time loop cannot
do.

**Degradation with failures:**

| Failures | Count | QP mean error | Learned mean error | Ratio | Learned % in bounds |
|---:|---:|---:|---:|---:|---:|
| 0 | 964 | 9.494661e-04 | 7.273390e-03 | 7.7× | 3.22 |
| 1 | 495 | 5.312145e-04 | 1.256916e-02 | 23.7× | 8.28 |
| 2 | 541 | 4.778948e-04 | 1.410363e-02 | 29.5× | 4.62 |

## 8. Uncertainty output

| Quantity | Value |
|---|---:|
| Pearson r(confidence, allocation error) | **−0.6245** |
| Pearson r(ensemble spread, allocation error) | +0.7045 |
| Mean ensemble spread / RMS command error | **0.6333** |

Error by confidence decile, lowest to highest:
2.564e-02, 1.581e-02, 1.301e-02, 1.079e-02, 8.762e-03, 7.679e-03, 6.632e-03,
6.001e-03, 5.343e-03, 4.658e-03 N·m.

The ranking is monotone across all ten deciles and spans 5.5× in error, so the
confidence is useful for *ordering* predictions by trustworthiness or for
gating a fallback to the exact QP.

It is **not calibrated**. The mean ensemble spread is 0.633 of the RMS command
error, so the members agree with each other more than they agree with the
truth, and the spread understates the error by roughly 37%. It must not be used
as a measurement covariance in a filter or a control loop.

It is also close to useless as a bound-violation predictor: even the top
confidence decile violates the actuator box on 92% of its samples.

## 9. Failure cases

- **Bound violations are the normal case, not the exception** (95.15% of test
  samples). Any use of the raw output must be followed by an explicit check.
- **Silent geometry mismatch.** The model is bound to one effector
  configuration. Applying it to a different `EffectorSet` with the same `m`
  returns a confidently wrong answer with no exception and no confidence signal.
- **Degradation with failures.** Error grows from 7.7× the QP at zero failures
  to 29.5× at two. Three or more simultaneous failures are outside the training
  distribution entirely and were not evaluated.
- **Commands outside the attainable set.** The model has no notion of the
  attainable moment set and cannot report infeasibility. `qp_allocate`,
  `lp_allocate` and `reallocate_after_failure` all can and do.
- **No stuck-open failures were trained.** The dataset fails effectors *off*
  only. A thruster stuck open shifts the attainable set off the origin, and
  the model has never seen that.
- **Extrapolation in magnitude.** Commands were sampled at up to 1.05× the
  degraded attainable boundary. Nothing is known about larger commands.
- **The confidence is not a safety signal.** See section 8.

## 10. Ethical and safety limits

Research-grade software. Not flight-qualified, not certified, not approved for
operational aerospace use. No DO-178C, ECSS-E-ST-40C or equivalent process was
followed and there is no independent verification.

**This model is not certified for operational flight use.** It must not be
placed in a spacecraft or aircraft control allocation path. On the evidence
above, the exact QP is more accurate, always feasible, and — for the single
allocations a real loop performs — faster, so there is no operating point on
this problem where the learned allocator is the right engineering choice.

Its legitimate uses are as a research baseline for anyone attempting a better
learned allocator, and as a measured counterexample to the assumption that a
network surrogate of a small QP is automatically a speed win.

## 11. Reproducibility

```bash
pip install -e ".[test]"
python validation/validate_ml_vs_qp.py    # ~180 s on 2 cores
python examples/ml_benchmark_demo.py      # reduced-size figure, ~30 s
```

Seeds: training data 1234, test data 5678, model `random_state=0` (members
0-4), gamma 1e12, `u_pref = 0`. All randomness goes through
`numpy.random.default_rng` and scikit-learn's `random_state`, so a run on the
same numpy / scikit-learn / BLAS build reproduces these digits. Last digits may
move on a different BLAS; the conclusions do not.
