# Dataset Card — TrackForge reacquisition environment

**Package:** `trackforge` 0.1.0 (product P002) · **License:** AGPL-3.0-only
**Type:** *generated environment*, not a collected dataset

> The "dataset" for the machine-learning component of TrackForge **is the
> simulator**. No files of samples are collected, distributed or committed:
> episodes are generated on demand from a seed. This card describes the
> generating process, its assumptions and its limits, with the same rigour a
> file-based dataset card would receive.

---

## 1. What the environment produces

One sample = one **loss-of-lock episode** from `trackforge.reacq.ReacqEnv`.
An episode is a sequence of decision points; at each one the environment
exposes

| Feature | Symbol | Unit | Observable by the agent |
|---------|--------|------|-------------------------|
| Time since loss of lock | t | s | yes |
| Last-known offset magnitude | \|p_lk\| | rad | yes |
| Estimated uncertainty growth | σ(t) | rad | yes |
| Radius already searched around the last-known position | r_searched | rad | yes |
| True target displacement at loss | δ₀ | rad | **no** (hidden) |
| Relative drift velocity | v_drift | rad/s | **no** (hidden) |
| Loss severity | u | – | **no** (hidden; only its effect on \|p_lk\| is visible) |

and returns, for each action, the elapsed scan time and whether the target
was found.

## 2. Generating process

Every quantity below is generated by committed code (`src/trackforge/reacq.py`)
and is deterministic given the seed.

```
u        ~ U[0, 1]                                  loss severity
|p_lk|   = sigma_lk * (0.5 + 2u)                    last-known offset      (10)
scale(u) = sigma_0 * (1 + kappa * u^2)              displacement scale     (11)
delta_0  ~ N(0, scale(u)^2 I_2)                     displacement at loss
v_drift  ~ N(0, drift_rate^2 I_2)                   relative drift
p_true(t)= p_lk + delta_0 + v_drift * t             true target track
sigma(t) = sqrt(sigma_0^2 + (drift_rate * t)^2)     tracker uncertainty    (12)
```

Attempt duration uses the uniform-coverage model of `trackforge.scan`:
covering area *A* at coverage rate `s·v` costs `A/(s·v)` seconds — a disc of
radius *R* costs `πR²/(s v)`, an annulus `r₁→r₂` costs `π(r₂²−r₁²)/(s v)`.
An attempt succeeds if the target (evaluated at the attempt's mid-point) lies
in the searched region **and** an independent Bernoulli(`p_detect`) trial
succeeds.

### Default parameter values

| Parameter | Value | Meaning |
|-----------|-------|---------|
| `sigma0` | 5.0·10⁻⁵ rad | post-loss estimate uncertainty |
| `sigma_lk` | 6.0·10⁻⁵ rad | scale of the last-known offset |
| `drift_rate` | 1.0·10⁻⁴ rad/s | 1σ relative drift rate |
| `cone_radius` | 1.0·10⁻³ rad | a-priori uncertainty cone |
| `coverage_rate` | 6.0·10⁻⁷ rad²/s | s·v of the scan |
| `p_detect` | 0.85 | per-attempt detection probability |
| `k_local`, `k_ring` | 3.0, 2.0 | LOCAL disc / RING width, in units of σ(t) |
| `kappa` | 10.0 | severity coupling in eq. (11) |
| `max_time` | 30.0 s | episode timeout |

With these values a `LOCAL` attempt at t = 0 costs 0.236 s and a `FULL`
attempt costs 5.24 s — a factor ≈22, which is what makes the decision
non-trivial.

## 3. Source and justification — read this before using any number

- Equations (10)–(12) are a **modelling choice made for this simulator**.
  They are *not* taken from any publication, mission report or measurement
  campaign, and no such source is claimed.
- Their purpose is to reproduce a qualitative trade-off that real PAT
  reacquisition logic faces: a violent loss-of-lock event both leaves the
  line of sight far off boresight (observable) and throws the target far from
  the last-known position (not observable), so an observable cue exists but is
  noisy. Cheap local re-scans win on easy losses; expensive full-cone
  re-scans win on hard ones.
- The *structure* of the acquisition problem — spiral/raster scan of a
  Gaussian uncertainty cone, track spacing tied to beam overlap, dwell-based
  detection — follows standard laser-communication PAT practice (see the
  survey by Kaymak et al. 2018, *IEEE Communications Surveys & Tutorials*
  20(2), and Hemmati (ed.) 2006, *Deep Space Optical Communications*). The
  *parameter values* above are illustrative orders of magnitude for a small
  optical terminal and are not design data for any system.
- Consequently: results obtained on this environment characterise **policies
  under this model**, not the performance of any real terminal.

## 4. Splits

There is no file split. Separation is by **random seed**:

| Split | Seeds | Size | Used for |
|-------|-------|------|----------|
| Training | one stream seeded by `train_q_learning(seed=...)`, default 12345 | 20 000 episodes | Q-learning updates |
| Held-out evaluation | environment re-seeded per episode to `eval_seed + i`, default 999…2998 | 2 000 episodes | all reported metrics |
| Seed sweep | training seeds 12345, 20260, 777 | 3 × 20 000 | generalisation spread |

The evaluation seeds are disjoint from the training stream and identical
across all policies compared (**common random numbers**), so policy
differences are not confounded by scenario sampling noise.

## 5. Size, format and storage

- Nothing is stored on disk. One episode is a few decision steps; a
  20 000-episode training run allocates only the 320 × 3 Q-table and visit
  table (≈15 kB total).
- Regeneration is deterministic: `train_q_learning(cfg, episodes=N, seed=S)`
  and `evaluate_policy(policy, cfg, n_episodes=N, seed=S)` reproduce bitwise
  identical results (verified in `tests/test_reproducibility.py`).

## 6. Known limitations and biases of the environment

1. **Assumed severity model.** Eqs. (10)–(11) impose a specific, monotone,
   quadratic coupling between the observable cue and the hidden displacement.
   A learned policy will exploit exactly that coupling; a different (e.g.
   weaker or non-monotone) real-world relation would invalidate the learned
   thresholds.
2. **Isotropic Gaussian everything.** Displacement and drift are isotropic
   Gaussians. Real pointing errors are often anisotropic (different az/el
   statistics) and heavy-tailed.
3. **Linear drift.** The target moves at a constant velocity after loss; no
   acceleration, no manoeuvre, no orbital curvature.
4. **Detection is a single Bernoulli per attempt** with a fixed probability,
   independent of SNR, dwell time, background or beam-pointing error inside
   the footprint. It does not model the multi-dwell structure of a real
   crossing (which V2 in `validation/VALIDATION.md` shows matters).
5. **Uniform-coverage timing.** Attempt durations use the same
   uniform-coverage approximation that V2 shows is ≈0.6 % optimistic against a
   dwell-by-dwell simulation for the acquisition case; the inner-turn regime
   is where it is weakest.
6. **Mid-point evaluation.** Target position is evaluated once, at the
   attempt's mid-time, rather than continuously along the scan. For long
   attempts with fast drift this slightly misstates coverage.
7. **No abort.** An attempt in progress is never abandoned, so the elapsed
   time can exceed `max_time` (reported times are censored at `max_time` in
   `evaluate_policy`).
8. **Discretisation bias.** The tabular state uses fixed bin edges tuned for
   the default configuration. They are not adaptive and will mis-bin other
   configurations.
9. **No noise on the observables.** The agent sees `|p_lk|` and σ(t) exactly.
   A real system estimates both, with error.

## 7. Ethical considerations

The environment contains no personal, human-subject or otherwise sensitive
data. It is entirely synthetic. The relevant risk is **misuse of the
results**: quoting benchmark numbers from this environment as if they
characterised a physical optical terminal. They do not.

## 8. Maintenance

Regenerate all environment-derived evidence with:

```bash
python validation/v5_reacq_benchmark.py    # policy benchmark
python validation/v7_regression_baseline.py  # pinned values
```

Any change to `ReacqConfig` defaults or to eqs. (10)–(12) invalidates the
pinned regression values and the learned policy, and must be recorded in
`CHANGELOG.md`.
