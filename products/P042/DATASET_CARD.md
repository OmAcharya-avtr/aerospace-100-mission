# Dataset card — acmpilot synthetic channel data 0.1.0

**This model is not certified for operational flight use, and this dataset is
not measured data.** Every sample is generated by committed code from a stated
seed. No scintillometer record, rain-gauge series, field link telemetry or
laboratory modem measurement appears anywhere in this package.

## What the data is

Two kinds, both synthetic.

### 1. SNR sample paths (used by the predictors and every policy)

A sequence of per-slot electrical SNR values in dB, produced by
`acmpilot.channel.snr_db_path(config, n_slots, seed)`:

* a stationary unit-variance first-order Gauss-Markov driver with lag-1
  correlation `exp(-slot/tau_c)`;
* mapped to a unit-mean irradiance, either lognormal or gamma-gamma (the latter
  through a Gaussian copula on two independent drivers, which preserves the
  gamma-gamma marginal exactly);
* mapped to SNR by `SNR_dB = SNR0_dB + 10 * detector_exponent * log10(I)`.

Reference configuration used for every published number: slot 1 ms,
`tau_c` = 10 ms, `sigma_I^2` = 0.5, SNR at mean irradiance 14 dB,
`detector_exponent` = 1 (coherent detection), lognormal marginal, with the
gamma-gamma marginal reported separately.

Because the mean of `10 log10(I)` is below `10 log10(E[I])`, the mean of the dB
path is about 13.0 dB, not 14.0 dB. That is correct and is not a normalisation
error.

### 2. Modulation symbols and bit errors (used to measure the MODCOD thresholds)

Uniform random symbols from a Gray-mapped unit-energy constellation through
complex AWGN, detected by minimum Euclidean distance
(`acmpilot.modulation.measure_ber`, `simulate_bit_errors`). Nothing is stored:
the measurement is run and only its summary — the BER curve and the derived
threshold table — is kept, in `validation/modcod_thresholds.json`, which is 4 kB
of JSON.

## Size, and why nothing large is committed

| artefact | size | committed? |
|---|---|---|
| `validation/modcod_thresholds.json` | about 4 kB | yes |
| SNR paths, one scored episode | 20 000 float64 = 160 kB | no, regenerated from the seed |
| training design matrix, one delay | about 15 580 x 7 float64 = 0.9 MB | no, regenerated from the seeds |
| BER Monte Carlo symbol streams | up to 4 x 10^7 symbols per validation run | no, never materialised in full; chunked at 50 000 |
| fitted quantile models | about 0.3 MB of joblib | no, `validation/artifacts/` is git-ignored |

Regeneration is deterministic: the same seed and the same library versions give
bit-identical paths (`tests/test_channel.py::TestPaths::test_snr_path_reproducible`).

## Seeds, and the split that keeps them apart

| purpose | seeds |
|---|---|
| fitting both predictors | 101, 102, 103 (5 200 slots each) |
| tuning every policy's free parameter | 201, 202, 203, 204, 205 |
| **every published score** | 301, 302, 303, 304, 305, 306, 307, 308, 309, 310 |
| held-out calibration path | 401 |
| MODCOD threshold Monte Carlo | 20261006 |
| policy sweeps in `validate_policies.py` | 1 … 5 |
| examples | small fixed seeds, stated in each script |

`acmpilot.benchmark.BenchmarkSplit` raises on any overlap between the first three
sets, so a leak is a construction error rather than a silent one.

## Generation command

```bash
python -c "
import sys; sys.path.insert(0, 'src')
from acmpilot.channel import ChannelConfig, snr_db_path
cfg = ChannelConfig(slot_s=1e-3, tau_c_s=10e-3, sigma_i2=0.5, mean_snr_db=14.0)
path = snr_db_path(cfg, 20000, 301)
print(path.size, path.mean(), path.std())
"
```

## Known limitations of the data

* **It is a model, not a measurement.** `tau_c` is an engineering knob standing
  in for a turbulence temporal spectrum set by transverse wind speed and the
  aperture-filtered Kolmogorov spatial spectrum, which is not a single
  exponential. Nothing in this package is evidence about a real link.
* **The fade-duration distribution is sampling-rate dependent.** Mean fade
  duration scales as about `tau_c**0.47` at a fixed 1 ms slot rate rather than
  `tau_c**1`, because the median fade stays pinned at 2 ms while only the tail
  lengthens (`validation/validate_channel.txt` V1.6). Resampling the same
  physical channel at a different slot rate changes the distribution.
* **The gamma-gamma correlation time is not the driver's.** The copula
  construction preserves the marginal exactly but makes the irradiance
  autocorrelation a monotone transform of the driver's, so the measured 1/e
  correlation time of a gamma-gamma path is 0.79 to 0.93 times `tau_c` depending
  on the scintillation index.
* **Deep fades are rare by construction.** At `sigma_I^2` = 0.5 the lowest
  MODCOD is unsupported in 0.028% of slots, so the slots that matter most are the
  ones the data contains least of. Raising `sigma_I^2` changes that and was not
  swept past 1.5.
* **The feedback report is noiseless.** It is the exact SNR of slot `n - d`. No
  quantisation, no measurement error, no lost report. Staleness is the only
  impairment, which is the point of the product and also makes every number here
  optimistic for a real terminal.
* **Within a slot the SNR is constant.** The usual block-fading idealisation,
  reasonable while 1 ms is short against a 10 ms correlation time and wrong if a
  user shortens `tau_c` towards the slot.
* **Bit errors are assumed independent within a codeword.** That is an
  interleaving assumption, and the interleaver it assumes is not modelled or
  charged for. `validation/validate_modcod_thresholds.txt` V2.3 measures what
  omitting the interleaver costs: up to 3.8% higher measured error rate than the
  model predicts for 16QAM.
* **No distribution shift is tested.** Nothing was measured about a predictor
  fitted at one correlation time, scintillation index, delay or marginal and
  applied at another.
