# Dataset Card — shacksim synthetic Shack-Hartmann stamps 0.1.0

> ## The data is 100 % synthetic, from an idealized optical model.
>
> **Every stamp and every frame used to train, tune and test this product is
> generated by `src/shacksim/sensor.py` from an idealized mathematical model of
> a lenslet array and a detector. No real wavefront sensor data, no laboratory
> measurement, no on-sky data and no flight data was used at any stage.**
> Reported accuracy therefore characterizes the estimators *against this model*,
> not against a physical sensor. Performance on real hardware is unknown and
> unmeasured, and because every unmodelled effect listed in §5 can only degrade
> results, these numbers are an **optimistic bound**.

**Producers:** `shacksim.sensor.generate_subaperture_dataset` (single-subaperture
stamps with exact slope labels) and `shacksim.sensor.simulate_frame` (full
detector frames).
**Committed to the repository:** no — the generator is committed, the data is not.
9000 training stamps regenerate in ≈ 0.4 s.
**Regeneration:** deterministic and bit-for-bit reproducible from a fixed integer
`seed` via `numpy.random.default_rng`.
**License:** Apache-2.0, the same as the code that produces it.

## 1. What a sample is

| Field | Type | Units | Description |
|---|---|---|---|
| `stamp` | `float64` `(p, p)`, default p = 16 | photoelectrons (e⁻) | One subaperture's detector pixels. **May be negative** — additive read noise is not clipped. |
| `slope` | `float64` `(2,)` | radians (m/m) | Exact wavefront gradient `(g_x, g_y)` that generated the stamp. |

For full frames the product is an `(image_size, image_size)` array in
photoelectrons with the illuminated subapertures filled and the masked-out
corners left at background only.

Labels are **exact by construction** — the slope is the parameter the stamp was
drawn from. There is no labelling noise, no annotator disagreement and no label
uncertainty. Real wavefront-sensor data never provides this.

## 2. Generative model

**Diffraction-limited spot size.** Behind a lenslet of clear aperture `d` and
focal length `f`, a circular unobscured aperture produces an Airy pattern of
full width at half maximum

```
FWHM = 1.0287938 · λ f / d       [m]
```

(Born & Wolf 1999, *Principles of Optics*, 7th ed., CUP, sec. 8.5.2 — the Airy
intensity `(2 J₁(v)/v)²` halves at `v = 1.61633`). The scaling is the physical
content: spot size grows linearly with wavelength and with f-number. For the
defaults (λ = 633 nm, f = 50 mm, d = 500 µm) this is 65.12 µm = 2.084 px.

**Spot profile.** The Airy core is approximated by a Gaussian of equal FWHM,
`σ = FWHM / 2.35482 = 0.8850 px`, integrated exactly over each pixel:

```
P(i, j) = N · [F_x(u+½) − F_x(u−½)] · [F_y(v+½) − F_y(v−½)]
F(u)    = ½ (1 + erf((u − c) / (σ√2)))
```

Axis-aligned elongation is available by using different `σ_x` and `σ_y`.

**Slope → displacement.** The wavefront gradient displaces the spot by
`Δx = f·g_x / p_pix` pixels (derivation in
`LensletArray.slope_to_displacement`; Hardy 1998, *Adaptive Optics for
Astronomical Telescopes*, OUP, ch. 5).

**Noise chain**, applied in this order (Thomas et al. 2006, *MNRAS* **371**, 323):

1. spot signal `N` distributed over the pixels as above;
2. `+ B` uniform background [e⁻/px];
3. Poisson shot noise on (signal + background), independent per pixel;
4. `+ N(0, R²)` additive Gaussian read noise, independent per pixel, not clipped.

## 3. Sampling distributions used in this product

| Parameter | Training | Held-out test |
|---|---|---|
| Photons per subaperture | log-uniform, 30 – 30 000 e⁻ | fixed per point: 30, 50, 100, 300, 1000, 3000, 10 000 e⁻ |
| Elongation | uniform, 1.0 – 3.0× along **x** | fixed: 1.0× and 3.0× |
| Slope `g_x`, `g_y` | uniform over ±0.6 × field = ±3.0 mrad | same |
| Background | 1.0 e⁻/px | 1.0 e⁻/px |
| Read noise | 3.0 e⁻ RMS | 3.0 e⁻ RMS |
| Stamp size | 16 × 16 px | 16 × 16 px |
| Size | 9000 stamps | 2000 stamps per point |
| Seed | 100 | `9000 + N + 7·elongation` |

Threshold tuning for the classical baseline uses a third, disjoint seed family,
`300 + N + 11·elongation`, so the baseline is never tuned on test data.

Slopes are drawn uniformly rather than from turbulence statistics. Real
atmospheric slopes are strongly spatially correlated (Kolmogorov) and have a
roughly Gaussian marginal distribution; **this dataset has neither property**,
and `shacksim.wavefront.random_slopes` says so explicitly in its docstring.
Consequently nothing here measures how any estimator behaves on turbulent
wavefronts.

## 4. Intended use

Benchmarking slope estimators against each other on a common, exactly labelled
substrate; teaching; regression-testing this package. **Not** a substitute for
sensor characterization data, and not a basis for any performance claim about
real hardware.

## 5. Unmodelled effects (what this dataset does NOT contain)

**Optics**

- Ring structure of the true Airy pattern — the Gaussian approximation has no
  rings and decays far faster than the real `r⁻³` envelope, so wing flux and
  hence the read-noise-weighted centroid tail are understated.
- Static and dynamic lenslet aberrations, wavefront curvature within a
  subaperture (only the mean gradient is represented), lenslet-to-lenslet focal
  length or pitch variation, array tilt, rotation and decentre relative to the
  detector.
- Chromatic effects — the model is strictly monochromatic. Real sources are
  broadband and the spot size scales with λ.
- Vignetting, partially illuminated edge subapertures (a subaperture is
  all-or-nothing here), scattered light, ghosting, and any optical crosstalk
  between neighbouring subapertures. A spot pushed beyond ±8 px is truncated
  rather than appearing in the neighbour, which real sensors do.
- Elongation at an arbitrary angle. Only axis-aligned elongation is
  representable, so the sodium laser-guide-star geometry — radial elongation
  whose angle and length vary across the pupil — is out of scope.
- Turbulence: there is no phase screen, no Kolmogorov spatial correlation, no
  temporal evolution, no scintillation (all subapertures get equal flux by
  default).

**Detector**

- Dead, hot and flickering pixels; cosmic-ray hits.
- Pixel-response and dark-signal non-uniformity (PRNU/DSNU), dark current,
  fixed-pattern noise, 1/f noise.
- Charge diffusion and pixel crosstalk; non-100 % fill factor and microlens
  effects; the model assumes a perfect square pixel with uniform response.
- Saturation, nonlinearity, blooming, ADC quantization and gain error.
- Frame-transfer smear, rolling-shutter effects, and any temporal correlation:
  each frame is independent.
- Excess noise factor of an EMCCD/APD, which is the detector one would actually
  use in the 30 e⁻ regime where the learned model wins.

**System**

- Alignment and calibration errors between the reference spot positions and the
  true optical axis (a real sensor's "null" is measured, not assumed).
- Non-common-path aberrations, thermal drift, vibration and jitter smear.

Every one of these can only make a real measurement worse than the simulation.

## 6. Provenance, versioning and maintenance

- Source of truth: `src/shacksim/sensor.py` at version 0.1.0.
- Any change to the generator changes the data; the package version must be
  bumped and the validation rerun. The numbers in `validation/VALIDATION.md` are
  tied to this version.
- No third-party data, no scraping, no personal data, no human subjects. There
  is nothing in this dataset that raises a privacy, consent or licensing
  question.

## 7. Known distributional limitations for the learned model

- Train and test are drawn from the **same** generative process with different
  RNG streams, so the reported accuracy is an in-distribution generalization
  measurement only. It does not bound performance under any distribution shift.
- The uniform slope prior means the model learns a shrinkage toward zero slope
  that is optimal for *this* prior and wrong for any other.
- The flux range spans three decades and the model is a single network across
  all of it, which is a large part of why its high-flux error floors at
  ≈ 0.1 px. A per-regime specialist would do better and is on the roadmap.
