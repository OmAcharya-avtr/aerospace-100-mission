6c. bus_reorder really reorders, and its rate is non-monotonic in swap_prob

    The mechanism holds one frame and may deliver the newer one first, so an
    exchange needs a swap followed by a non-swap. At swap_prob = 1 every step
    swaps, the held frame is never released, and nothing arrives out of order;
    the rate peaks near swap_prob = 0.5. This non-monotonicity is real and is
    recorded in the README limitations.

     swap_prob   swaps  out of order       first 8 source steps
    ------------------------------------------------------------
           0.1       4             4 [None, 0, 1, 2, 3, 4, 5, 6]
          0.25      17            13 [None, 0, 2, 1, 3, 4, 6, 5]
           0.5      27            14 [None, 0, 2, 1, 3, 4, 6, 5]
          0.75      46            11 [None, 1, 2, 3, 0, 5, 6, 7]
           1.0      59             0 [None, 1, 2, 3, 4, 5, 6, 7]

    Pure one-step delay when no swap fires: searching fault seeds at
    swap_prob = 0.1 for a 20-step run with zero swaps.
    fault seed 2: sources [None, 0, 1, 2, 3, 4, 5, 6] ... == one-step delay: True
