# Model card — safemodetree learned fault classifier 0.1.0

**This model is not certified for operational flight use.**

Research-grade. Not flight-qualified, not certified, not approved for
operational aerospace use. It is trained on synthetic data produced by the same
declaration it is evaluated against, and it has never seen a measurement from
any vehicle.

## 1. Problem

Given one observation vector over the declared channels of a
`safemodetree` declaration, output a probability for each declared fault and
for the no-fault class, well enough calibrated that a fault-response policy can
act on the number rather than on the argmax.

The point is the probability, not the label. The policy in
`safemodetree.policy` consumes the top-label probability: an identification
below a declared confidence threshold is abandoned and the class-conservative
response is commanded instead. A model that returns only a label cannot drive
that decision.

Formally: a 9-class classification over a 7-dimensional real observation
vector, for the shipped `reaction_wheel_fmea` declaration. The classes are
`nominal` plus the eight declared faults. Channel units are A, s, deg, V, A,
dimensionless and mN*m respectively; the model standardises them, so the units
do not enter the fit.

## 2. Baseline, implemented and measured first

`safemodetree.baseline.ThresholdLogicClassifier`. This is what onboard fault
detection, isolation and recovery logic normally is, and it was written and
benchmarked before the learned model existed.

Decision rule, entirely declared and nothing fitted:

1. Each channel's symptom bit asserts when the measurement is strictly beyond
   the declared threshold in the declared direction, by at least `margin_sd`
   multiples of the channel's declared `noise_sd`. The declared operating point
   is `margin_sd = 0`.
2. An all-zero symptom word is the no-fault class, confidence 1.
3. A symptom word equal to exactly one declared signature identifies that
   fault, confidence 1.
4. A symptom word equal to the shared signature of an ambiguity class of size
   `m` returns the lexicographically first member, confidence `1/m`.
5. Any other word resolves to the declared signature(s) at minimum Hamming
   distance `d`, returning the first of the `m` tied faults with confidence
   `1 / (m (1 + d))`.

Rule 5 is a **declared heuristic, not a probability estimate**. It is the
honest version of what threshold logic can offer as a confidence, and its
calibration error is one of the things measured here rather than assumed.

A second baseline is implicit and is the one that bounds both: the **accuracy
ceiling imposed by the declared observability model**, `accuracy_ceiling`. Four
of the eight shipped faults sit in declared ambiguity classes of size two with
identical observation distributions, so `(800 + 400 + 200) / 1600 = 0.875` is
the most any rule can reach on the shipped test split. Measured ceiling on that
split: **0.874062**. No detector exceeded it.

## 3. Architecture

`sklearn.pipeline.Pipeline` of `StandardScaler` then
`LogisticRegression(C=1.0, solver="lbfgs", max_iter=2000)`, multinomial,
wrapped in `CalibratedClassifierCV(method="isotonic", cv=5, ensemble=True)`.

Parameter count: 9 classes x 7 features plus 9 intercepts = **72** fitted
coefficients in the base estimator, plus the isotonic step functions of the
calibration wrapper (5 folds x 9 classes). No deep network, no GPU, no PyTorch.

Why a linear model is the correct choice and not a simplification: the
generator draws each class from an isotropic Gaussian with the **same**
covariance (see `data.py`), so the Bayes-optimal boundary between any two
classes is a hyperplane and the Bayes-optimal posterior is exactly
multinomial-logistic. A tree ensemble would approximate the same boundary with
axis-aligned steps and would be strictly worse specified. Choosing a bigger
model here would be a way of losing on purpose.

Why a calibration wrapper on an already-correctly-specified model: the base
posterior is correctly specified in form but is fitted on 3200 rows with L2
regularisation, which shrinks the coefficients and therefore flattens the
posterior. Isotonic regression on held-out folds corrects the resulting
monotone distortion (Zadrozny and Elkan, KDD 2002). The `sigmoid` option
(Platt 1999) and `none` are both exposed, because which wins is empirical.

Calibration options are a constructor argument, not a hidden default:
`LearnedFaultClassifier(calibration="isotonic" | "sigmoid" | "none")`.

## 4. Dataset source and limitations

See [DATASET_CARD.md](DATASET_CARD.md) for the full description. In summary:

- **Fully synthetic**, generated by `safemodetree.data.make_observations` from
  the declaration itself. No real telemetry of any kind.
- For a fault with declared signature `s`, channel `j` is drawn from
  `N(faulted_j, (noise_scale x noise_sd_j)^2)` when `s_j = 1` and
  `N(nominal_j, (noise_scale x noise_sd_j)^2)` otherwise. The nominal class is
  the all-zero signature.
- **Channels are independent.** Real symptom channels are correlated and often
  heavy-tailed, and a real onboard monitor latches through a persistence filter
  rather than on one sample. None of that is modelled.
- **Two faults in the same declared ambiguity class have IDENTICAL observation
  distributions, by construction.** The generator does not leak a difference the
  declaration denies. This is deliberate: it means the measured within-class
  accuracy of any classifier is the class prior, and the calibrated posterior
  tops out near `1/m`, which is exactly what the policy needs to see.
- `noise_scale` is a declared, dimensionless difficulty multiplier. At
  `noise_scale = 1` every declared threshold sits between 3.6 and 5.0 sigma
  from both the nominal and the faulted mean, so both detectors are nearly
  perfect and the comparison is uninformative. **Every benchmark here is
  therefore reported as a function of `noise_scale`, not at one value.**
- The dataset is generated at run time and **no data file is committed**. It is
  a deterministic function of the declaration, the arguments and the seed.

## 5. Training procedure

| item | value |
|---|---|
| samples per fault | 400 |
| nominal fraction | 0.5 (so 3200 nominal and 3200 faulted rows, 6400 total) |
| split | 50 per cent train, 25 per cent calibration, 25 per cent test (3200 / 1600 / 1600) |
| split method | plain random permutation, **not stratified**; per-class counts in each part are reported by `ObservationSet.counts()` |
| seed | 63001 for the generator, 63002 for the split |
| features | the 7 raw channel values, standardised by the pipeline |
| fit time | under 1 s on two contended cores |
| optimiser | lbfgs, `max_iter=2000`, converged |
| calibration | isotonic, 5-fold, `ensemble=True` |

**Nothing is tuned on the test split.** The learned detector's
declare-a-fault threshold `tau` is chosen on the **calibration** split, by
matching the baseline's false-alarm rate measured on that same split. The test
split is touched once, by both detectors, after both operating points are
fixed.

## 6. Metrics

All on the 1600-row test split. Full tables and the raw run in
[validation/VALIDATION.md](validation/VALIDATION.md) section 6 and
`validation/validate_calibration_output.txt`.

### Identification accuracy at an equal false-alarm rate

False-alarm rate is the fraction of no-fault rows at which some fault is
declared. Identification accuracy is the fraction of faulted rows identified as
the right fault; a missed detection counts as wrong.

| noise scale | baseline FAR | learned FAR | baseline ident. acc. | learned ident. acc. | delta | winner |
|---|---|---|---|---|---|---|
| 1.0 | 0.00000 | 0.00368 | **0.74650** | 0.72739 | -0.01911 | threshold logic |
| 1.5 | 0.02209 | 0.01595 | **0.74522** | 0.74013 | -0.00510 | threshold logic |
| 2.0 | 0.12147 | 0.07117 | 0.73503 | 0.73503 | +0.00000 | tie |
| 2.5 | 0.27239 | 0.26135 | 0.71592 | **0.71720** | +0.00127 | learned |
| 3.0 | 0.40859 | 0.44172 | 0.68153 | **0.70064** | +0.01911 | learned |

**The headline result, kept unsoftened: the learned classifier does not beat
the declared threshold baseline.** Two wins, two losses, one tie over five
noise scales, with the largest margin in either direction being 0.019 of
accuracy. The baseline is near the Bayes boundary for this generator, so
beating it was never likely, and a reader should not take the learned model as
the better detector on this problem.

### Calibration

Expected calibration error, top-label, Guo et al. 2017 equation 3, at three bin
counts because binned ECE is a biased estimator whose value depends on the
binning:

| noise scale | detector | ECE@5 | ECE@10 | ECE@20 |
|---|---|---|---|---|
| 1.0 | threshold logic | **0.00156** | **0.00156** | **0.00156** |
| 1.0 | learned | 0.01478 | 0.01567 | 0.01611 |
| 1.5 | threshold logic | 0.00778 | **0.00778** | **0.00778** |
| 1.5 | learned | **0.00588** | 0.00816 | 0.01162 |
| 2.0 | threshold logic | 0.02689 | 0.02783 | 0.02783 |
| 2.0 | learned | **0.02448** | **0.02448** | 0.02901 |
| 2.5 | threshold logic | 0.05521 | 0.05521 | 0.05521 |
| 2.5 | learned | **0.04972** | **0.04972** | **0.05256** |
| 3.0 | threshold logic | 0.07371 | 0.07371 | 0.07576 |
| 3.0 | learned | **0.06431** | **0.06463** | **0.06634** |

Lower ECE at 10 bins at **3 of 5** scales. The pattern is the finding: the
declared threshold logic is extremely well calibrated when the thresholds sit
far from the noise (**it beats the learned model at scale 1.0**) and becomes
steadily overconfident as the noise grows (0.00156 to 0.07371), because its
confidence is a lookup on a latched symptom word and carries no information
about how close the measurement was to the threshold. The learned posterior
degrades more slowly (0.01567 to 0.06463).

Multi-class Brier score (Brier 1950) of the learned posterior: 0.12924, 0.13893,
0.16237, 0.19523, 0.23383 at the five scales. The baseline has no posterior over
all classes, so it has no Brier score; this is reported as `-` rather than
filled in with something.

Maximum calibration error is reported beside ECE and is noisy by construction:
the baseline's MCE at scale 2.0 is 0.66667, from a bin holding **2**
predictions. Bin occupancy is printed in the reliability table and plotted on a
log scale in `screenshots/calibration_reliability.png` so that a sparse bin
cannot be read as a result.

### What the model is for, measured

Routing on the posterior, learned detector, `fine_pointing`, threshold 0.70,
783 commanded fault events:

| policy | mean cost [min] | mis-routed | conservative fraction |
|---|---|---|---|
| oracle (perfect identification) | 23.4535 | 0 | 0.0000 |
| always fault-specific | 35.4866 | 206 | 0.0000 |
| confidence routed | 44.6322 | **6** | 0.6181 |
| always conservative | 53.0000 | 0 | 1.0000 |

Cost of conservatism: **+21.1787 min** per commanded event against the oracle,
**+9.1456 min** against the always-specific policy, buying the elimination of
**200 of 206** mis-routes — 35.81 min of declared outage per avoided mis-route.

**And the sign is not universal.** With the declared threshold logic in
`coarse_pointing` the cost of conservatism against the always-specific policy is
**-2.3278 min**: routing conservatively is cheaper *and* safer there, because
that detector's identifications are wrong often enough that the mis-route
penalty exceeds the conservative route. Both numbers come from the same test
split and both are reported. Full table in VALIDATION.md section 7.

## 7. Test-split strategy

Three-way split by a single random permutation with a fixed seed: 50 per cent
train, 25 per cent calibration, 25 per cent test. The calibration split exists
specifically so the operating point can be chosen without touching the test
split; the baseline's false-alarm rate is measured there and the learned
threshold is matched to it there.

The split is **not stratified**, so per-class proportions differ between the
three parts by sampling noise. `ObservationSet.counts()` reports the per-class
counts in each part and the counts are in the committed validation output.

There is no cross-validation at the top level. The 5-fold cross-validation
inside `CalibratedClassifierCV` is over the **training** split only.

## 8. Uncertainty and confidence output

- `predict_proba(features)` returns the full `(n, 9)` posterior, rows summing
  to 1 within 1e-9. Asserted in `tests/test_learned.py`.
- `confidence(features)` returns the top-label probability, dimensionless in
  [0, 1].
- `fault_probability(features)` returns one minus the no-fault posterior; this
  is the quantity the detection threshold is swept over when matching a
  false-alarm rate.
- `learned_decisions(model, features, tau)` is the deployed rule: below `tau`
  of total fault mass the detector declares no fault and reports the no-fault
  posterior as its confidence; at or above it the detector declares the most
  probable **fault** and reports **that fault's unnormalised posterior**. The
  unnormalised number is deliberate: the policy's question is "what is the
  probability this specific fault is the cause", and that is the quantity it
  needs, not a renormalised one.

**A hard ceiling on the confidence, by construction.** Two faults in the same
declared ambiguity class have identical observation distributions, so the
top-label posterior for a member of a class of size `m` cannot systematically
exceed `1/m`. `tests/test_learned.py::test_confidence_inside_an_ambiguity_class_cannot_exceed_one_half`
asserts that the mean of the larger of the two posteriors over star-tracker
rows is below 0.60, a loose bound that would still fail if the model separated
them. The policy's confidence threshold of 0.70 therefore routes essentially
every ambiguity-class row to the conservative response, which is the intended
behaviour and not a coincidence.

## 9. Failure cases

1. **Inside an ambiguity class the model is at chance and knows it.** It cannot
   do better, and the calibrated posterior reports that honestly. If a reader
   wants those two faults separated, the fix is a new observation channel in the
   declaration, not a bigger model.
2. **It loses to the declared thresholds at low noise** (scales 1.0 and 1.5) on
   both identification accuracy and ECE. On a quiet system the declared logic is
   simply better and cheaper.
3. **Missed detections.** At the matched operating point, 2 of 785 faulted test
   events in `fine_pointing` produce no commanded response at all. Those are
   counted and never costed, because any cost put there would be invented.
4. **False alarms cost real outage.** At the matched operating point the
   confidence-routed policy spends a mean of **0.5693 min** of declared outage
   per no-fault test row on responses to faults that were not there. The
   always-specific policy spends **3.7595 min**, nearly seven times more,
   because it commands a specific response on every spurious identification.
5. **Out-of-distribution input is not detected.** The model has no novelty
   score. An observation vector unlike anything in training still returns a
   posterior over the nine declared classes, and `fault_probability` will not
   flag it. This matters: the no-fault class is a Gaussian blob around the
   declared nominal vector, so a genuinely new failure mode will be assigned to
   whichever declared fault it happens to resemble, with a confidence that may
   be high.
6. **Operating-point transfer.** `tau` is chosen on a calibration split drawn
   from the same generator. On data from a different distribution the matched
   false-alarm rate will not hold, and nothing here measures how fast it drifts.
7. **Matching a zero false-alarm rate leaves a residual.** At scale 1.0 the
   target rate is exactly 0 and the matched threshold gives a test-split rate of
   0.00368. Recorded, not tuned away.

## 10. Reproducibility — exact commands and seeds

From the repository root, with `pip install -e ".[test,plot]"` done:

```bash
PYTHONPATH=src python validation/validate_calibration.py
PYTHONPATH=src python validation/validate_conservatism.py
PYTHONPATH=src MPLBACKEND=Agg python examples/detector_vs_threshold.py
PYTHONPATH=src MPLBACKEND=Agg python examples/calibration_reliability.py
PYTHONPATH=src MPLBACKEND=Agg python examples/conservatism_tradeoff.py
python -m safemodetree benchmark --noise-scale 2.0 --n-per-fault 400 --seed 63001
python -m safemodetree policy --noise-scale 2.0 --n-per-fault 400 --seed 63001 --sweep
```

Seeds: **63001** for the observation generator, **63001 + 1 = 63002** for the
train/calibration/test permutation, and `63001 % 10000 = 3001` for the
estimator's `random_state`. The plotting tests use 63002 for the generator to
stay independent of the benchmark. The 2000 random declarations of the
reachability cross-check use seeds **0 to 1999**.

The committed validation output was reproduced byte-for-byte at **both ends of
every declared dependency range** — scikit-learn 1.5.2 and 1.9.1, numpy 2.1.3
and 2.5.3 — which is the check that catches a model whose numbers move while
its tests still pass. See VALIDATION.md section 9.

**No model artifact is committed.** The classifier is fitted at run time from a
seeded generator, so there is no pickle whose format could break across a
scikit-learn release. The scikit-learn bound is nonetheless pinned to the minor
version, because the measured numbers are its outputs.

## 12. Ethical and safety limits

- **This model is not certified for operational flight use.** It is a
  demonstration on synthetic data from its own declaration.
- It is not a fault detector for a real spacecraft, a real aircraft, or any
  other real system. It has never been shown a real measurement.
- Using it to identify a fault on a real vehicle, or to set a real FDIR
  confidence threshold, is a decision this package does not support and
  provides no evidence for.
- The declared threshold-logic baseline beats it as often as it loses to it on
  this problem. Replacing a reviewable, declared threshold table with a fitted
  model is a loss of reviewability and it should be justified by measured gain;
  here there is no accuracy gain to justify it, only a calibrated confidence,
  and that is all this package claims.
- The cost accounting is in declared outage minutes. It credits nothing for
  retained mission capability and nothing for crew or payload risk, so it must
  not be used as the sole criterion for choosing a fault response.
- There is no personal data, no human subject, and no demographic attribute
  anywhere in this package. The fairness questions that apply to models about
  people do not arise; the reviewability question above does.
