# Dataset card — crossing events for fade-duration exceedance

Everything in this card is synthetic and generated by committed code in this
repository. There is no measured data in this product and no third-party dataset is
used, redistributed or relied on.

## What one record is

One record is a **down-crossing event**: the instant at which a seeded amplitude
path falls below a fixed threshold. Each record carries

- 10 float features computed from the 32 amplitude samples **ending at the crossing
  sample** (`codedfade.predictor.FEATURE_NAMES`), with no sample after the crossing
  entering any feature;
- the realised fade duration in samples;
- a binary label, 1 if that duration exceeds `t_target`;
- the path seed it came from, used as the split group.

## Generation

`codedfade.predictor.build_dataset`, from `codedfade.channel.generate_amplitude`.
One path per seed:

| Parameter | Value |
|---|---|
| marginal | lognormal |
| correlation kernel | `exp` (Gauss-Markov / AR(1) filtered Gaussian) |
| scintillation index `SI` | 0.6 |
| correlation time `tau` | 2.0e-4 s |
| sample rate `fs` | 1.0e6 Hz (one sample per code symbol) |
| correlation length `Lc = tau*fs` | 200 samples |
| samples per path | 200 000 (0.2 s of channel, 1000 correlation times) |
| threshold amplitude | 0.6, with `E[a**2] = 1` |
| `t_target` | 14 samples = 1.4e-5 s |
| random source | `numpy.random.default_rng(seed).standard_normal(n)` |

The amplitude is `a = sqrt(I)` with `I` lognormal, unit mean, log-irradiance
variance `ln(1 + SI)`.

## Splits

| Split | Path seeds | Paths | Events | Exceedance frequency |
|---|---|---|---|---|
| train | 0–23 | 24 | 39 687 | 0.199486 |
| held out | 100–111 | 12 | 19 900 | 0.198693 |

**The split is by path seed, not by event.** Crossings from one realisation are
correlated with one another through the shared sample path, so splitting events at
random would put near-duplicate events on both sides and inflate every held-out
figure. The seed ranges are disjoint and far apart.

`t_target = 14` was chosen as approximately the mean fade duration at this
configuration (sample 15.5 samples, analytic 15.26 samples), which puts the class
balance near 20/80. It was **not** tuned to make any result look better; it is
fixed in `validation/train_model.py` and in the validation script, and changing it
changes the problem rather than the score.

## Size on disk

Nothing is committed. The dataset is regenerated from seeds in about 20 s on one
core, which is cheaper than storing it and removes any possibility of the committed
data drifting from the generator. The only committed artefact is the fitted model,
`validation/fade_exceedance_model.joblib`.

## Known limitations of the data, and what they invalidate

- **One regime only.** A single scintillation index and a single correlation time.
  Any claim that the model generalises across turbulence conditions is
  unsupported — none is made.
- **One kernel only.** The `exp` kernel. The `gauss` kernel has materially
  different short-fade statistics (its continuous-time crossing rate is finite,
  whereas the `exp` kernel's is not), so a model trained here should not be applied
  to it.
- **Lognormal only.** No gamma-gamma events are in the dataset.
- **Frozen, stationary channel.** No pointing jitter as a separate process, no beam
  wander, no time-varying mean, no background light, no receiver dynamics. Those
  are folded into `SI` and `tau` by assumption, not modelled.
- **Discrete sampling.** Fade durations are integer multiples of `1/fs`. The median
  fade is 3 samples, so the duration distribution is coarsely quantised at the short
  end, and a fade shorter than one sample is invisible. At `Lc = 200` samples this
  affects the short tail, not the `t_target = 14` decision, but it would at a lower
  sample rate.
- **Censoring.** Runs touching either end of a record are excluded, by the
  definition in `codedfade.fade`. With 200 000 samples per path and a maximum fade
  around 600 samples this removes at most one event per path.
- **Self-evaluation.** The data and the evaluation come from the same channel model,
  so any systematic error in that model is invisible to every metric in
  `MODEL_CARD.md`. This is the single most important limitation and no amount of
  held-out splitting addresses it.
