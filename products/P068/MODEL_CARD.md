# Model card — degradepredict learned crossing-time forecaster

**Version 0.1.0 · 2026-10-16 · Apache-2.0 · © 2026 OPTIMA Organisation**

**This model is not certified for operational flight use.**

The software is research-grade. It is not flight-qualified, not certified, and
not approved for operational aerospace use. Every number in this card was
produced by a script in `validation/` in this repository and is traceable to
the output file named beside it.

## Problem

A subsystem health metric sampled from housekeeping telemetry is drifting
toward a declared limit. Given the window of telemetry available now, produce a
**distribution over the time at which the metric will cross that limit**, and
have the interval around it be calibrated — including for the units that have
not crossed yet, which are the majority.

The shipped instantiation is battery usable capacity in percent of
beginning-of-life against an 80 percent end-of-life limit, with service age in
days. Nothing in the model is specific to batteries beyond the shape family of
the physics-shaped baseline.

## Baseline, implemented and validated first

Three analytic baselines exist in `src/degradepredict/baselines.py` and
`physics.py` and were written, tested and validated before any learned model.
All three are ordinary least squares of a transformed metric on a transformed
time, inverted for the crossing, with an exact Fieller (1954) confidence set
and a delta-method interval:

| baseline | model | source for the shape |
|---|---|---|
| `linear` | `y = y0 - b t` | first-order expansion; no mechanism claimed |
| `exponential` | `y = y0 exp(-k t)` | loss rate proportional to the remaining metric; no mechanism claimed |
| `powerlaw-fade` | `y = y0 (1 - B t**z)`, `z = 0.55` | Wang et al. (2011), J. Power Sources 196(8):3942-3948, who fit capacity loss as a power law with exponent 0.55; the z = 0.5 diffusion-limited regime is Broussely et al. (2005), J. Power Sources 146(1-2):90-96 |

The interval machinery was validated on correctly specified data before being
used on anything else: over eight configurations of shape, window length and
noise, Fieller coverage ranges from 0.8835 to 0.9405 against a nominal 0.90
(`validation/validate_baselines_output.txt`).

## Architecture

- Seven independent `sklearn.ensemble.GradientBoostingRegressor` models with
  `loss="quantile"`, one per level in `(0.05, 0.10, 0.25, 0.50, 0.75, 0.90,
  0.95)`.
- Target: `log` of the remaining life in days from the forecast origin.
- `n_estimators=300`, `max_depth=3`, `learning_rate=0.05`,
  `min_samples_leaf=10`, `subsample=0.9`, `random_state=0`.
- Inputs: 19 lag and shape features from the telemetry window
  (`src/degradepredict/features.py`), each with a declared unit.
- Output: the seven fitted quantiles, rearranged by a cumulative maximum to
  remove quantile crossing (Chernozhukov, Fernandez-Val and Galichon 2010,
  Econometrica 78(3):1093-1125), wrapped in a `QuantileForecast` that
  interpolates linearly in probability between them and holds the tails flat.
- No model is serialised. Every figure in this repository comes from a fit
  performed in the run that produced it, so there is no pickle format to bound.

Reference for the estimator: Friedman (2001), Annals of Statistics
29(5):1189-1232. Reference for the loss: Koenker and Bassett (1978),
Econometrica 46(1):33-50.

## Censoring

Most units have not crossed. A complete-case fit on the ones that did is
biased toward fast units. Censored units enter the fit through **inverse
probability of censoring weights**: the censoring distribution `G` is estimated
by Kaplan-Meier (1958) with the roles of event and censoring swapped, and each
uncensored unit is weighted by `1 / G(T-)` (Graf et al. 1999, Statistics in
Medicine 18(17-18):2529-2545). Weights are capped at a declared 20 and
normalised to mean 1.

`weighting="none"` reproduces the naive complete-case fit and is shipped so the
bias can be measured rather than asserted. Neither censored quantile regression
(Portnoy 2003) nor Buckley-James imputation (1979) is implemented; both are
better estimators than IPCW and both are absent.

## Dataset

Synthetic, generated by `src/degradepredict/generate.py`, regenerable from a
seed. Full description and limitations in `DATASET_CARD.md`. Shipped split:
1200 training trajectories at seed 20261016 and 400 test trajectories at seed
20261017; the seeds are disjoint so no unit appears in both.

Headline dataset properties (`validation/validate_headtohead_output.txt`):

- Training: 502 complete, 698 right-censored (58.17 percent censored).
- Test: 173 complete, 227 right-censored (56.75 percent censored).
- Test true remaining life: median 402 d for complete units, 1126 d for
  censored ones. The censored units are the long-lived ones, which is why a
  pooled score is a weighted average of two different problems.

**Dataset limitations that bound every result here.** No flight data. Gaussian
independent observation noise with no autocorrelation, no temperature
dependence, no outliers and no quantisation. Censoring independent of the
degradation state by construction, which a real fleet usually violates. Three
declared mean shapes and no regime changes. A fixed 7-day cadence with no gaps.

## Training procedure

```bash
python validation/validate_headtohead.py   # fits and scores everything
```

1. Generate 1200 training trajectories at seed 20261016.
2. Compute the 19-feature matrix from each unit's window.
3. Compute IPCW weights from the observed durations and event flags; censored
   rows get weight 0 and the uncensored rows are reweighted.
4. Fit seven quantile GBMs on `log(remaining life)` over the 502 uncensored
   rows with those sample weights.

No hyperparameter search was run. The settings above were chosen to fit inside
the compute budget and were not tuned against the test set.

## Test-split strategy

Train and test populations are generated from **different seeds**
(20261016 and 20261017) through the same generator, so the split is by unit and
no trajectory, window or label is shared. Every model, learned or analytic, is
scored on the same test units with the same forecast origins. Stability is
reported over three disjoint seed pairs.

### A baseline wins and the win is not removed

**On right-censored trajectories — 56.75 percent of the test set — the
exponential baseline beats the learned forecaster on both CRPS (346.37 d
against 435.56 d) and pinball loss (166.72 d against 212.57 d).** It wins on
all three independent seed pairs tested. The learned forecaster wins on
complete trajectories by a wide margin (30.80 d against 90.74 d CRPS). There
are two winners and they are different models. This result is research
evidence; it has not been retuned, reweighted or removed, and any future change
to this repository that makes it disappear has to explain why.

The mechanism is not mysterious. The learned model is fitted on units whose
crossing was observed, which are the short-lived ones, and it therefore
predicts short. IPCW pulls it back (censored CRPS 461.05 to 435.56, censored
coverage 0.3172 to 0.3348) and does not pull it back far enough. The analytic
baselines have no such bias because they never see a training set at all: they
extrapolate each unit's own window.

## Uncertainty and confidence output

The output **is** a distribution; there is no point estimate with an
uncertainty bolted on. `CrossingForecast.quantile(p)` gives the quantile
function of the remaining life in days, `interval(level)` the equal-tailed
central interval, `cdf(r)` the predictive CDF. The analytic baselines carry a
normal law on the transformed crossing time and additionally report Fieller's
`g` and the exact Fieller set, which is **unbounded** when `g >= 1`; the
delta-method interval stays bounded in exactly that case and is therefore the
one that lies.

Honest statement of what the uncertainty covers: for the baselines it is
parameter uncertainty under an assumed shape and nothing else — no term for
the shape being wrong. For the learned model it is whatever the quantile
regression learned from the training distribution, which is a biased sample of
the population. Both are measured above and both are badly short of nominal.

## Failure cases

1. **Right-censored units.** Coverage 0.3348 against a nominal 0.90. The model
   predicts too short a remaining life for long-lived units. This is the
   dominant failure and it is a direct consequence of the training-label
   censoring.
2. **A declared physics exponent that is slightly wrong.** With `z` fitted at
   0.55 and true `z` at 0.45, the crossing estimate is biased by -180.93 d on a
   1200 d crossing while the interval is 62 d wide; coverage is 0.0000
   (`validation/validate_physics_output.txt`).
3. **A shape outside the fitted family.** The linear baseline covers 0.8629 on
   linear units and 0.0127 on power-law units.
4. **A window with no significant decline.** Fieller's `g` exceeds 1 on 17.59
   percent of randomly drawn windows in the sweep, and the exact confidence set
   is then a half line. The baselines refuse to report a crossing when the
   fitted slope is not negative; the harness substitutes a declared
   uninformative fallback and counts it (3, 1 and 0 fallbacks on the shipped
   test set).
5. **Tail saturation of the learned CDF.** The predictive CDF is an
   interpolation of seven fitted quantiles, so a realisation beyond the 0.95
   quantile returns a PIT of exactly 0.95 and the CRPS of a tail miss is
   understated.
6. **The field cannot see most of the failure.** Only 0.0396 of the learned
   model's censored intervals are falsified by the censoring alone, against a
   true non-coverage of 0.6652. A deployment measuring what it can measure
   would see about six percent of the problem.

## Reproducibility

Exact commands, from the repository root, Python 3.11 or later:

```bash
pip install -e ".[dev]"
python -m pytest tests/ -q --junitxml=junit.xml
python validation/validate_crossing.py
python validation/validate_baselines.py
python validation/validate_physics.py
python validation/validate_headtohead.py
python validation/validate_calibration.py
python validation/validate_cli.py
python validation/worked_example.py
```

Seeds, all fixed in the scripts: generator train 20261016, generator test
20261017, stability pairs 20261116/20261117 and 20261216/20261217, boosting
`random_state=0`, baseline sweeps 20261016 + 1, + 2 and + 3.

Determinism: each candidate trajectory draws from its own
`numpy.random.SeedSequence` child, so the k-th accepted unit is identical for
any population size at or above k and the selection step for one unit cannot
perturb another. `python -m degradepredict generate` produces a byte-identical
CSV on a second run with the same seed
(`validation/validate_cli_output.txt`).

## Ethical and safety limits

- **This model is not certified for operational flight use.**
- No maintenance, replacement or disposal decision should be taken from this
  model's output. Its censored coverage is 0.3348 against a nominal 0.90, which
  means the interval it prints is wrong about two thirds of the time for the
  units that matter most.
- No constant in this repository was identified from any spacecraft, battery,
  reaction wheel or mission. The 80 percent end-of-life convention is borrowed
  from IEEE Std 1188-2005 and is declared, not derived.
- The generator is a declared synthetic process. Any result here transfers to
  real telemetry only to the extent that the generator resembles it, and the
  dataset card lists the ways in which it does not.
- The independent-censoring assumption that IPCW rests on is usually false in a
  real fleet, where units are removed because they are degrading. In that
  situation the weighting is biased in a direction this repository cannot
  measure.
