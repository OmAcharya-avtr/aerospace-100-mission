# Dataset Card — WaveLab synthetic slopes-to-Zernike dataset 0.1.0

> ## The data is 100% synthetic, generated from an idealized turbulence and geometry model.
>
> **Every sample used to train, tune and test the learned reconstructor in this
> product is generated by `src/wavelab/dataset.py` from a synthetic Kolmogorov
> phase screen (`wavelab.screens.kolmogorov_screen`), an analytic point-sampled
> Zernike gradient forward model, and a simplified shot-noise-only slope error
> model. No real Shack-Hartmann sensor data, no laboratory measurement, no
> on-sky data and no flight data was used at any stage.** Reported accuracy
> therefore characterizes both the learned model and the classical baseline
> *against this generative process*, not against a physical sensor or
> atmosphere. Every unmodelled effect listed in §5 can only make real
> performance worse than these numbers, so they are an **optimistic bound**.

**Producer:** `wavelab.dataset.generate_batch`.
**Committed to the repository:** no. A batch of 2000 samples regenerates in a
few seconds; nothing here exceeds the mission's "no committed artifact over
1 MB" rule because nothing is committed at all.
**Regeneration:** deterministic and bit-for-bit reproducible from a fixed
integer `seed` (see `wavelab.dataset.generate_batch` docstring for the exact
per-sample seed derivation).
**License:** Apache-2.0, the same as the code that produces it.

## 1. What a sample is

| Field | Type | Units | Description |
|---|---|---|---|
| `slopes` | `float64` `(2 * n_sub,)` | dimensionless, per unit normalised pupil radius | Noisy subaperture-centre wavefront slopes, x-block then y-block. Zero at any subaperture the dropout draw marked inactive. |
| `active` | `bool` `(n_sub,)` | -- | True where the subaperture is kept; False = dropped out. |
| `coeffs` | `float64` `(n_modes,)` | radians | Ground-truth Noll-Zernike coefficients (piston excluded) the sample's screen was fitted to. |

Labels are **fit-derived, not exact**: `coeffs` comes from a least-squares fit
of the raw FFT-generated phase screen to a finite Zernike basis
(`wavelab.zernike.fit_zernike`), so it omits whatever screen content the
chosen mode set (default Noll `j = 2..15`) cannot represent. This differs
from a fully "exact by construction" label (e.g. drawing coefficients
directly and evaluating the screen from them) and is a deliberate choice:
using a real, spatially-correlated phase field as the source is what "from
Kolmogorov phase screens" in the mission scope means, at the cost of a
(small, high-order) label-truncation error that a coefficients-first design
would not have.

## 2. Generative model

**Turbulence.** `wavelab.screens.kolmogorov_screen` synthesizes a phase
screen from the Kolmogorov power spectral density (Roddier 1981, *Prog.
Optics* **19**, 281-376) via the FFT method (McGlamery 1976, *Proc. SPIE*
**74**, 225; discretization after J. D. Schmidt, *Numerical Simulation of
Optical Wave Propagation*, SPIE Press, 2010, Sec. 9.3). `r0/D` is drawn
uniformly per sample from `r0_over_d_range` (default `(0.10, 0.35)`).

**Zernike fit.** The screen, masked to the unit disc, is least-squares fitted
to Noll modes `j = 2..J_MAX` (`wavelab.zernike.fit_zernike`), giving the
sample's `coeffs` label.

**Forward slope model.** The noise-free slope vector is the *analytic* point-
sampled Zernike gradient at each subaperture centre,
`s_true = zernike_slope_matrix(...) @ coeffs` (`wavelab.zernike`), **not** a
finite-difference of the raw screen. This means the label and the slope are
mutually exact given the fitted coefficients -- the truncation error is
entirely absorbed into how well `coeffs` represents the original screen (§1),
and no additional discretization error is introduced by the slope step
itself.

**Noise chain**, applied in this order (`wavelab.dataset.generate_batch`):

1. `slope_sigma(photon_flux)` shot-noise-only Gaussian noise added to every
   slope component independently (`wavelab.noise.add_slope_noise`);
2. a subaperture-dropout mask drawn independently per subaperture at the
   requested rate (`wavelab.noise.apply_dropout`); slopes at dropped
   subapertures are zeroed in the returned array, and the mask itself is
   returned as an explicit feature.

## 3. Sampling distributions used in this product

| Parameter | Default range / value |
|---|---|
| `r0/D` (Fried parameter / pupil diameter) | uniform, 0.10 - 0.35 |
| Noll modes reconstructed | `j = 2..15` (14 modes, up to radial order 4) by default; `j = 2..9` in the smaller example/CLI configurations |
| Subaperture layout | `n_side x n_side` square grid masked to the unit disc (default `n_side=8`, giving 32 active subapertures) |
| Photon flux | scenario-dependent; validation sweeps 100 - 10 000 |
| Dropout rate | scenario-dependent; validation sweeps 0.0 - 0.6 |
| Screen grid | 64 x 64 (mission compute-budget default) |

Training data for the learned model (`validation/validate_dropout.py`) uses a
single **mixed** operating point (flux 800, dropout 0.25) rather than the
sweep values themselves, so every reported evaluation point in the flux and
dropout sweeps is out of the exact training distribution in at least one
dimension -- this is stated explicitly because it is the reason the model is
not simply memorizing the test conditions.

## 4. Intended use

Training and benchmarking `wavelab.ml.ZernikeSlopeEnsemble` against
`wavelab.modal.ModalReconstructor` on a common, deterministic substrate;
regression-testing this package. **Not** a substitute for real Shack-Hartmann
sensor data or real atmospheric turbulence statistics, and not a basis for any
performance claim about physical adaptive-optics hardware.

## 5. Unmodelled effects (what this dataset does NOT contain)

**Turbulence and optics**

- Temporal evolution (frozen-flow or otherwise); every sample is an
  independent, static screen.
- Scintillation, anisoplanatism, cone effect, and any effect that couples
  turbulence at different altitudes (the model is a single equivalent-layer
  Kolmogorov screen).
- Outer-scale and inner-scale effects (`kolmogorov_screen` implements the pure
  power-law PSD with no `L0`/`l0` cutoff).
- The FFT generation method's own known low-spatial-frequency deficit
  (module docstring of `wavelab.screens`; Lane, Glindemann & Dainty 1992,
  *Waves in Random Media* **2**, 209) -- subharmonic compensation is **not**
  implemented, so large-scale content (tip/tilt and low-order aberrations in
  particular) is systematically under-represented relative to true Kolmogorov
  statistics. This directly affects the relative magnitude of low- vs
  high-order Zernike coefficients in every sample.

**Sensing**

- No detector, spot, or centroiding physics at all -- slopes are the
  *analytic* Zernike gradient plus abstract Gaussian noise
  (`wavelab.noise.slope_sigma`), not a simulated pixel-level measurement.
  Compare `wavelab.noise`'s module docstring and the fuller, pixel-level
  treatment in the related product ShackSim (P018), which this package does
  not duplicate.
- The photon-noise model omits background and read noise (which scale with
  detector window area, not just photon count) and any spot-shape dependence.
- Dropout is drawn independently per subaperture with a single scalar rate;
  no spatially correlated dropout (e.g. a shadowed sector of the pupil) is
  modeled.
- The slope forward model is *point-sampled* at each subaperture centre, not
  averaged over the subaperture area -- exact only where the wavefront varies
  slowly across one subaperture (`wavelab.zernike.zernike_slope_matrix`
  docstring).

**System**

- No optical misalignment, non-common-path aberration, vibration, or
  calibration error.
- No obscuration (`PupilGrid` supports one, but the dataset generator does
  not use it by default).

Every one of these can only make a real measurement worse than the
simulation.

## 6. Provenance, versioning and maintenance

- Source of truth: `src/wavelab/dataset.py`, `wavelab/screens.py`, and
  `wavelab/noise.py` at version 0.1.0.
- Any change to any of these three modules changes the data; the package
  version must be bumped and `validation/` rerun. Numbers in
  `validation/VALIDATION.md` and `MODEL_CARD.md` are tied to this version.
- No third-party data, no scraping, no personal data, no human subjects.
  Nothing here raises a privacy, consent, or licensing question.

## 7. Known distributional limitations for the learned model

- Training uses one fixed (flux, dropout) point; the model must extrapolate
  to every other sweep point, which is a harder and more honest test than
  training on the sweep distribution itself, but also means training-point
  proximity (flux 800-1000, dropout ~0.25) is where the learned model is
  closest to its best achievable relative performance.
- The uniform `r0/D` prior and the fixed Noll mode range mean the learned
  model's implicit prior over coefficient magnitude is whatever this sampling
  produces, not a general statement about atmospheric statistics.
- See `MODEL_CARD.md` §9 for the measured, sometimes large, performance gap
  between the learned model and the classical baseline at high flux.
