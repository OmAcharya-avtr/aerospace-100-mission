==============================================================================
5b. The input grid itself, which is a larger error than the integrator
==============================================================================
This check FAILED on its first run and the failure is the finding, kept
here rather than removed. Refining the grid also refines the zero-order
hold on the exogenous inputs, and the eclipse edge at
0.65 * 5700 s = 3705 s is NOT a multiple of 30 s, so a 30 s grid places
that edge up to 15 s away from where a 3.75 s grid places it. The
resulting temperature difference is far larger than the integrator's own
error measured in 5a.

eclipse edge                       = 3705.000 s
edge / dt                          = 123.5000  (not an integer)
worst |T(30 s grid) - T(3.75 s grid, true edges)| = 0.625662 K
ratio to the integrator error in 5a = 131399.1
ratio to the thermometer noise      = 2.086

CONSEQUENCE, recorded in README Limitations: the zero-order-hold input
grid is part of the model, not an implementation detail. Every number in
this repository is internally consistent because the data generator and
the fitter use the same grid, so the quantisation cancels exactly. A real
calibration against real telemetry would not have that cancellation and
would carry this as a model error of order 0.6 K on this design.
verdict: REPORTED, not bounded
