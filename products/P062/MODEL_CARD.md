**This model is not certified for operational flight use.** The software it
ships in is research-grade:
**not flight-qualified, not certified, and not approved for operational aerospace use.**

## Problem

A digital twin of a spacecraft unit is a parameterised physics model. After its
parameters are fitted to telemetry, the measurements and the model still differ,
and that difference contains three things that the data alone cannot separate:
measurement noise, parameter error, and **model-form error** — structure the
model cannot produce at any parameter value.

The model in this card learns the model-form part. It is a *discrepancy* model
in the sense of Kennedy and O'Hagan (2001): given features computed from the
fitted physics run, it predicts the residual, and the twin's prediction becomes
`physics + learned residual`.

The question it exists to answer is not "can a flexible regressor reduce the
held-out error" — it can — but **how much of that reduction is real and how much
is the regressor standing in for parameters the data cannot determine.** That is
measured here, two ways, and reported whether or not it is flattering.

## Baseline, implemented and measured first

Weighted nonlinear least squares on the physics model alone
(`twincalib.fitting.fit`), which for independent Gaussian errors of known
variance is maximum likelihood. It was written, validated and measured before
the residual model existed, and the residual model is scored against it on the
same held-out observations with the same metric.

The baseline's own validation — recovery of known parameters, Cramer-Rao
efficiency, profile-interval coverage — is in `validation/VALIDATION.md`
sections 4 to 6.

**The baseline wins or ties on the design where there is nothing to learn, and
the residual model never improves the physical parameters on any design where it
improves the predictions.** Both facts are in the metrics below.

## Architecture

`sklearn.gaussian_process.GaussianProcessRegressor` with kernel

```
ConstantKernel(1.0, (1e-10, 1e6)) * RBF(1.0, (1e-3, 1e4)) + WhiteKernel(sigma_T^2, (1e-8, 1e4))
```

- `normalize_y=True`, so the target mean and scale are removed before fitting.
- Hyperparameters chosen by marginal likelihood (Rasmussen and Williams 2006,
  Chapter 5), one restart from a random point in the bounds, seeded.
- Features standardised by the **training set's** mean and standard deviation; a
  constant column is left centred at zero rather than divided by a zero scale.
- The bounds are deliberately wide because on one shipped design the amplitude
  legitimately collapses towards zero — there is nothing to learn — and that is a
  result, not a fitting failure, so the bound must not clip it.

Why a Gaussian process rather than a forest or a boosted ensemble: it returns a
predictive standard deviation that is a genuine posterior quantity for its own
assumptions, so the uncertainty output is not bolted on. The cost is
`O(n^3)` fitting and `O(n^2)` prediction, which is why the training set is capped
(below).

### Features

Six, all computable from the physics run and the known inputs. **The feature
builder does not take the measurements at all**, which is what makes it usable on
a held-out trajectory and on a real one.

| feature | meaning | unit |
|---|---|---|
| `T1_model` | physics-predicted unit temperature | K |
| `T2_model` | physics-predicted panel temperature | K |
| `dT_model` | `T1_model - T2_model`, the interface drop the discrepancy acts on | K |
| `dissipation` | measured unit dissipation at that sample | W |
| `sun` | illumination fraction | dimensionless |
| `is_channel_T2` | which thermometer the sample belongs to | 0 or 1 |

Structural check: two records of the same design and phase that differ in noise
seed by up to **1.488763 K** produce feature matrices differing by
**0.000e+00** (`validation/validate_residual.py` check 6).

## Dataset: source and limitations

Fully synthetic, generated by committed scripts from fixed seeds. See
[`DATASET_CARD.md`](DATASET_CARD.md).

- **Source.** `twincalib.scenarios.make_dataset`, from a two-node lumped thermal
  network (Gilmore 2002, Chapter 1) with declared parameters and a declared
  temperature-dependent interface conductance as the model-form discrepancy.
- **No telemetry from any spacecraft was used, and no parameter value in the
  generating model is a measurement of flight hardware.** The magnitudes are
  justified against cited material properties and the solar constant, which is
  not the same thing.
- **Limitations that matter for this model.** The discrepancy has one declared
  functional form, and a model that learns it well here has not been shown to
  learn anything else. The thermometer noise is independent and Gaussian with a
  known standard deviation, which real housekeeping chains are not. The
  exogenous inputs are known exactly. The zero-order-hold input grid is part of
  the model (README Limitations 1), and the residual model inherits that.

## Training procedure

1. Generate `n_train` training trajectories of one design, evenly spaced in
   input phase over `[0, 0.5)`, with noise seeds `base_seed + i`.
2. Fit the physics parameters to **one** training trajectory, because a
   calibration campaign gives you one record.
3. Build features and residuals for **all** training trajectories at that one
   fitted parameter vector, because telemetry is cheaper than campaigns.
4. Cap the pooled training set at `max_training_points` (default 600) by taking
   an **evenly spaced** subset, so that the time coverage of every trajectory is
   preserved; the offered and used counts are both recorded.
5. Fit the Gaussian process.

Default configuration for the published numbers: `n_train = 4`, `n_test = 3`,
`base_seed = 4200`, `max_training_points = 600`, so **1604 samples offered and
600 used**.

## Test-split strategy

Whole trajectories, held out two ways at once:

- **by input phase** — training phases are evenly spaced over `[0, 0.5)` and
  test phases over `[0.5, 1)`, so the dissipation and eclipse timing differ;
- **by noise seed** — training seeds are `base_seed + i`, test seeds are
  `base_seed + 1000 + i`.

No test sample appears in training in any form, and the physics fit never sees a
test trajectory either.

## Metrics

All on held-out trajectories only. Source:
`validation/validate_residual_output.txt`.

### Held-out prediction

| design | true discrepancy RMS [K] | noise [K] | physics RMSE [K] | combined RMSE [K] | improvement | verdict |
|---|---:|---:|---:|---:|---:|---|
| `baseline-eclipse` | 0.5537 | 0.300 | 0.6642 | 0.4052 | **+0.3899** | residual wins |
| `full-sun` | 0.9795 | 0.300 | 0.4816 | 0.3187 | **+0.3382** | residual wins |
| `lumped-nodes` | 0.1268 | 0.300 | 0.3051 | 0.2993 | **+0.0189** | **tie** |
| `weak-excitation` | 0.6171 | 0.300 | 0.3363 | 0.3200 | +0.0485 | residual wins |

The decision margin is 2 per cent relative; inside it the verdict is a tie,
because a comparison of two root-mean-square errors differing in the fourth
decimal is not a result.

### Uncertainty output

`predict` returns `(mean, std)`. The reported band is
`sqrt(std^2 + sigma_T^2)`, a predictive interval for a new measurement.

| design | coverage at nominal 0.9500 | coverage at nominal 0.6827 | mean GP sd [K] |
|---|---:|---:|---:|
| `baseline-eclipse` | 0.9709 | 0.7573 | 0.333346 |
| `full-sun` | 0.9900 | 0.8313 | 0.305800 |
| `lumped-nodes` | 0.9933 | 0.8437 | 0.299475 |
| `weak-excitation` | 0.9900 | 0.8221 | 0.303518 |

**Every figure is above nominal, so the interval is conservative — too wide, not
too narrow.** That is the safer direction to be wrong in and it is still wrong.
An interval reported as 95 per cent that covers 97 to 99 per cent is **not
calibrated** and must not be quoted as a 95 per cent interval. It is usable as a
conservative bound and as a ranking signal.

### Absorption, measurement 1: subspace decomposition

The learned residual field on held-out data is projected onto the three
orthogonal subspaces of the physics sensitivity matrix at the fitted parameters:
`strong` (the parameters could have done this and the data would have seen it),
`weak` (the parameters could have done this and the data cannot tell — **the
absorption term**), `orthogonal` (no parameter value can do this — genuine
model-form error).

At the default cut `s/s_max = 1e-2`:

| design | strong | **weak** | orthogonal |
|---|---:|---:|---:|
| `baseline-eclipse` | 0.35463 | **0.00161** | 0.64375 |
| `full-sun` | 0.03637 | **0.12715** | 0.83648 |
| `lumped-nodes` | 0.99512 | **0.00011** | 0.00476 |
| `weak-excitation` | 0.97137 | **0.00140** | 0.02723 |

**The statement this supports.** On the structurally non-identifiable design the
learned residual puts a far larger share of its energy into directions the data
cannot constrain, while showing a *similar* held-out improvement (+0.3382
against +0.3899). A reader looking only at the improvement could not tell the two
designs apart.

**The statement it does not support.** Any particular ratio. Across six
configurations of training-set size and noise seed
(`validation/validate_absorption_output.txt`) the ratio swings from **3.34 to
96.74**. What survives is a separation: `full-sun`'s absorption fraction stays in
**[0.08144, 0.15605]** and `baseline-eclipse`'s in **[0.00161, 0.02441]**, and
the two ranges are disjoint.

**Threshold sensitivity.** At `1e-3` the weak fractions are 0.00000 / 0.08159 /
0.00000 / 0.00102 and the ordering holds. At `1e-1` the ordering **inverts**,
because at that cut only one of six parameter directions counts as strong. The
measure is meaningful only for cuts below the sensitivity spectrum's own second
value, which is 6 to 9 per cent of the first here.

### Absorption, measurement 2: parameter drift

Refit the physics with the learned discrepancy subtracted, and compare the
parameters with the truth (Brynjarsdottir and O'Hagan 2014).

| design | RMS log error, physics only | with residual | verdict |
|---|---:|---:|---|
| `baseline-eclipse` | 0.132553 | 0.178772 | **WORSE** |
| `full-sun` | 0.076650 | 0.091097 | **WORSE** |
| `lumped-nodes` | 0.040403 | 0.034044 | better |
| `weak-excitation` | 4.684348 | 4.863888 | **WORSE** |

**The headline, unsoftened.** On `baseline-eclipse` the residual model reduces
the held-out error by **39 per cent** and makes the physical parameters **35 per
cent worse** in root-mean-square log error, on the same experiment. The
per-parameter drift is `q_par` **+0.10638** and `h_rad` **+0.04073** in natural
log units, while the training chi-squared falls from 1628.25 to 864.00.

**If the deliverable is a prediction, use the residual model. If the deliverable
is a physical parameter — a heat capacity to put in a thermal report — the
residual model is actively harmful, and the physics-only fit with its profile
intervals is the thing to report.**

## Failure cases

1. **It makes the physical parameters worse on three of four designs**, and the
   one design where they got better is the one where the predictions did not.
2. **Its uncertainty is not calibrated.** It over-covers on every design
   measured, by 2 to 4 percentage points at the 95 per cent level and 7 to 16 at
   the 68 per cent level.
3. **On a structurally non-identifiable design 12.7 per cent of its learned
   field lies in directions the data cannot constrain** (against 0.16 per cent
   on the sound design), so part of its improvement is compensating for
   parameters that are not determined.
4. **It finds nothing when there is nothing to find, which is correct, and the
   verdict machinery then reports a tie rather than a win.** On `lumped-nodes`
   the fitted amplitude collapses to **7.64e-05** with the white-noise term at 1.
   A user who reads only the improvement figure (+0.0189) might take it for a
   small real gain; it is noise-level and the decision margin exists to say so.
5. **It generalises across input phase and noise seed, and nothing here shows it
   generalises anywhere else.** A different discrepancy form, a different design,
   a different temperature band: untested.
6. **The published numbers move with the library versions.** At
   scikit-learn 1.8.0 / SciPy 1.16.0 the whole test suite still passes and the
   `full-sun` absorption fraction moves from **0.12715 to 0.04621**, because a
   different kernel is fitted. The dependency ranges are pinned one minor version
   wide for that reason; see `validation/VALIDATION.md`, "Dependency range
   measurement".
7. **The training set is capped at 600 points** and the cap is reached on every
   multi-trajectory design. A larger cap would fit a different model; nothing
   here measures how much better.

## Reproducibility

Exact commands, from the repository root. Every figure in this card comes from
the first of them.

```bash
pip install -e ".[dev]"
python validation/validate_residual.py     # every metric in this card
python validation/validate_absorption.py   # the stability of the absorption figure
MPLBACKEND=Agg python examples/residual_benchmark.py
MPLBACKEND=Agg python examples/absorption_subspaces.py
python -m twincalib residual --design baseline-eclipse
```

Seeds and settings, all defaults of `twincalib.benchmark.run_benchmark`:

| setting | value |
|---|---|
| `n_train` / `n_test` | 4 / 3 |
| `base_seed` | 4200 (training seeds 4200-4203, test seeds 5200-5202) |
| training input phases | 0.000, 0.125, 0.250, 0.375 |
| test input phases | 0.500, 0.667, 0.833 |
| `residual_seed` (GP restarts) | 0 |
| `max_training_points` | 600 |
| `decision_margin` | 0.02 |
| `strong_cuts` | 1e-1, 1e-2, 1e-3 |
| thermometer noise | 0.3 K, known to the fitter |

Environment of the published run: Python 3.13.16, NumPy 2.5.3, SciPy 1.18.1,
scikit-learn 1.9.1, two contended CPU cores.

## Ethical and safety limits

- **This model is not certified for operational flight use.**
- It must not be used to produce a physical parameter for a thermal report, a
  margin calculation or a design decision. It is measured to make the physical
  parameters **worse** on three of four designs, and that is its defining
  property, not an edge case.
- Its uncertainty output must not be quoted as a calibrated confidence level. It
  over-covers, and a reader told "95 per cent" would be misled about the shape
  of the distribution even though the bound is conservative.
- A twin corrected by a learned discrepancy term can track telemetry closely
  while its parameters drift away from physical reality. If such a twin is used
  for anomaly detection, the detector inherits the drift: the residual model can
  absorb the very change an operator needs to see. P053 TwinInvalidate exists
  for the detection question and nothing here replaces it.
- All data is synthetic. No human-subject data, no personal data and no
  proprietary telemetry is involved at any point.
- The model is a regression on six scalar features of a two-node thermal
  simulation. It has no capability beyond that and no plausible dual use.
