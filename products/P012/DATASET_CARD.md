# Dataset Card — NavBench Adaptive-Q Training Set

**Dataset name:** `navbench.adaptive.generate_adaptive_dataset` output
**Version:** 0.1.0 · **Date:** 2026-08-29 · **Owner:** OPTIMA Organisation
**License:** AGPL-3.0-only (the generator; the data is regenerated, not shipped)

> **This dataset is entirely synthetic.** It is generated by a committed,
> seeded script from a mathematical model. It contains no measurement from any
> real vehicle, sensor or flight. Any accuracy figure computed on it measures
> agreement with *that generative process*, not with reality.

---

## 1. What it contains

One row per sliding window of a simulated Kalman-filter run:

| field | shape | description |
|---|---|---|
| `features` | (K, 6) | the scale-free innovation statistics of `navbench.adaptive.innovation_features` (see MODEL_CARD §3) |
| `targets` | (K,) | `u = log₁₀(q̃_true / q̃_nominal)`, the quantity to be recovered |
| `run_index` | (K,) | which simulation run the window came from, so splits can be made run-wise |

Default size: **150 runs → 2550 rows**. Rows from one run are *not* independent
of each other; splits must be made by `run_index`, and the benchmark in
`validation/v6_adaptive_q_benchmark.py` uses disjoint seed ranges rather than a
row-wise shuffle for exactly this reason.

## 2. Generating process

Per run `i` (seed `20260812 + i`):

1. Draw `u ~ Uniform(−1.5, 1.5)`, so `q̃_true = 0.05 · 10^u m²/s³` spans
   0.00158 … 1.58114 m²/s³ (1/32 to 32 times nominal).
2. Simulate 400 steps of a 1-D continuous-white-noise-acceleration
   constant-velocity truth, `dt = 1 s`, state `[position m, velocity m/s]`,
   `x₀ = [0, 1]`:
   `F = [[1, T], [0, 1]]`, `Q_true = q̃_true [[T³/3, T²/2], [T²/2, T]]`
   (Bar-Shalom, Li & Kirubarajan 2001, Eq. (6.2.3-4)).
3. Generate position-only measurements, `H = [1, 0]`, `σ_z = 3 m`.
4. Run a `KalmanFilter` with the **nominal** `Q` (`q̃ = 0.05`), `P₀ = diag(100, 10)`,
   `x̂₀ = [0, 0]`.
5. Emit one feature vector per sliding window of the innovation sequence,
   length 40, stride 20, starting at step 40 — 17 windows per run.

Everything is deterministic given the seed. Re-running the generator reproduces
the arrays bit-for-bit; this is pinned by
`tests/test_regression.py::TestPinnedAdaptiveDataset` and
`tests/test_adaptive.py::test_deterministic`.

## 3. Why the data is not committed

At 2550 × 6 float64 the array is ~120 kB, well under the 1 MB threshold — but it
is committed as **a generator, not a file**, because a regenerable dataset
cannot drift out of sync with the code that produced it. Regeneration costs
about 8 s:

```bash
cd products/P012
PYTHONPATH=src python3 -c "
from navbench import generate_adaptive_dataset
x, y, idx = generate_adaptive_dataset(n_runs=150, n_steps=400, seed=20260812)
print(x.shape, y.shape, idx.shape)"
```

## 4. Splits

| split | seeds | runs | rows |
|---|---|---|---|
| train | `20260812 + i`, `i ∈ [0, 150)` | 150 | 2550 |
| held out | `20260812 + 100000 + i`, `i ∈ [0, 60)` | 60 | evaluated per run, not per window |

The ranges are disjoint by construction. Held-out runs are evaluated end to end
(the filter runs causally over the whole 400 steps) rather than as isolated
windows, because that is how the tuner is actually used.

## 5. Distribution and known biases

* `u` is **uniform in log space**, so the dataset is symmetric between
  under- and over-specified `Q`. A real fleet's mis-tuning distribution is
  unlikely to be uniform or symmetric.
* The nominal `q̃` sits at the geometric centre of the range. This deliberately
  makes the fixed baseline as strong as it can be.
* Every run uses the **same** measurement noise `σ_z = 3 m`, the same `dt`, the
  same `P₀` and the same initial state. Nothing in the dataset varies the
  measurement model, so the learned tuner cannot have learned to distinguish a
  `Q` problem from an `R` problem — and it will mis-attribute an `R`
  mis-specification to `Q`. This is a real limitation, not a hypothetical one.
* Only one measurement channel (`m = 1`). Features 4 and 5 are therefore
  identical in every training row, so feature 5 carries no information in this
  release; it exists so the same feature vector works for `m ≥ 2`.
* No manoeuvres, no coloured noise, no outliers, no dropouts. The dataset is
  clean in a way real telemetry never is.

## 6. Intended and unintended uses

**Intended.** Training and benchmarking process-noise scale estimators inside
this package; teaching the relationship between innovation statistics and
filter tuning; reproducing the benchmark in `validation/VALIDATION.md` §6.

**Not intended.** Any claim about real vehicle behaviour; any model destined for
a flight system; any use where the synthetic origin is not carried forward into
the conclusions.

## 7. Provenance and maintenance

* Generated by `src/navbench/adaptive.py::generate_adaptive_dataset` at version
  0.1.0.
* Contains no personal data, no third-party data, and no data of restricted
  provenance.
* If the truth model, sensor model, filter or feature definitions change, the
  dataset changes. The regression tests pin the current values so that such a
  change is visible rather than silent.
