# Dataset card: the committed fixture history and seeded-fault set

Version 0.1.0 · 2026-10-15

Research-grade. Not flight-qualified, not certified, not approved for
operational aerospace use.

Three committed datasets, all under `fixtures/`, all regenerated by one script:

```bash
python fixtures/regenerate_fixtures.py
```

---

## 1. `fixtures/sample_project/` -- the bundled sample project

A small numerical Python project, written for this product, with a deliberately
layered import structure so that reachability has a non-trivial answer.

| property | value |
|---|---|
| source modules | 7 plus the package `__init__` |
| test modules | 7 |
| test nodes | 24 |
| clean run | 24 tests, 0 failures, 0 errors, 0 skipped |

Import structure, which is what Baseline 1 reads:

```
vecops  stats  integrate  orbit        leaves, no local imports
quat       -> vecops
filters    -> stats
kinematics -> quat, vecops
```

`fixtures/sample_project/junit.xml` is the junit XML of a clean full-suite run
and is a **committed deliverable**, not an artifact. It is the one fixture that
is not byte-reproducible: pytest writes a timestamp, a hostname and a per-test
duration into every junit report. Its content -- test ids, counts, outcomes --
is identical across runs, and that is what `tests/test_mutation.py` asserts.
`history.json`, `generation_parameters.json` and `fault_matrix.json` are
byte-identical across runs at seed 20261015, checked with `md5sum`.

The `junit.xml` fixture is reachable on a cold clone through the repository
root's `!products/*/fixtures/**/junit.xml` negation; the measurement is in
`validation/validate_fixtures_output.txt`.

**Limitations.** Seven modules and twenty-four tests. The modules are largely
independent and there is no shared utility module and no `conftest.py`, so the
dependency baseline's selection fraction on this project (mean 0.3214 over
single-module changes) is lower than on a real suite.
`validation/validate_self_selection_output.txt` measures the same baseline on
this repository's own suite, with and without the conftest coupling, for
contrast.

## 2. `fixtures/faults/` -- seeded faults and the measured fault matrix

`faults.json` declares 14 single-line textual substitutions written as
classical mutation operators: arithmetic and relational operator replacement,
constant replacement and swap, unary operator deletion, condition deletion,
statement deletion, index replacement and an off-by-one.

`fault_matrix.json` is the **measured** result of applying each one to a
throwaway copy and executing the suite. Nothing in it is asserted.

| property | value |
|---|---|
| seeded faults | 14 |
| detected by the full suite | 10 |
| full-suite detection upper bound | 0.714286 |
| detected by no test | F04, F12, F13, F14 |
| cost to regenerate | 15 pytest processes, 12.0 s on 2 cores |

The four undetected faults are real holes in the sample project's own suite:

| fault | module | operator | why no test sees it |
|---|---|---|---|
| F04 | `quat` | `-` to `+` in the Hamilton product x term | the four quaternion tests do not exercise a quaternion with a non-zero vector part on both operands in the affected term |
| F12 | `orbit` | `<=` to `<` in a radius guard | only `period` has a zero-radius test; `circular_velocity` does not |
| F13 | `kinematics` | half a length guard deleted | no test passes a wrong-length rate vector |
| F14 | `stats` | sample-count guard loosened | no test passes a single-sample series to `variance` |

They are kept in every denominator. Dropping them would let a strategy read as
perfect on a suite that is not.

**Limitations.** Fourteen hand-seeded faults are not an exhaustive mutant set
and the detection rates are properties of this fault set on this project. They
are not an estimate of a mutation score for anything else.

## 3. `fixtures/history/history.json` -- the revision history

**Synthetic.** Generated by `fixtures/regenerate_fixtures.py` at seed
20261015. Not mined from a real repository.

| property | value |
|---|---|
| revisions | 320 |
| revisions with at least one failing test | 116 (0.3625) |
| test nodes | 24 |
| failing node-observations | 478 |
| file size | 92 KB |
| schema | `regressselect-history/1` |

Each revision records its id, the changed modules, per-module churn in lines,
and the pytest node ids that failed.

### Generation model

Declared in full in `fixtures/history/generation_parameters.json`, written out
beside the data so every claim about the history can be checked against the
model that produced it.

| parameter | value |
|---|---|
| changed modules per revision | drawn from (1, 1, 1, 2, 2, 3) |
| module change weights | vecops 0.22, quat 0.18, kinematics 0.15, stats 0.12, filters 0.12, integrate 0.10, orbit 0.08, package `__init__` 0.03 |
| churn per changed module | uniform integer 2 to 80 lines |
| fault-proneness per module | kinematics 0.45, quat 0.40, filters 0.35, vecops 0.30, stats 0.25, integrate 0.20, orbit 0.15, package `__init__` 0.10 |
| regression probability | `1 - prod(1 - proneness_m * severity_m)` with severity linear in churn from 0.30 to 1.00 |
| failure probability for a reachable test | `sensitivity_t * 0.90^(hops-1)`, sensitivity drawn once per node from U(0.35, 0.95) |
| out-of-closure coupling rate | 0.010 per unreachable test per regression revision |
| flake rate | 0.003 per test per revision, independent of the change |

The last two parameters matter more than the rest. They are the reason the
dependency baseline's measured safety loss is 0.172072 and not zero: a
selection that is safe with respect to the declared import graph is still
unsafe against a failure that reaches the test through a channel the graph
cannot see, and against a failure the change did not cause at all. Both
channels are declared rather than hidden so that the 0.172072 is interpretable.

### Train/test split

Chronological at 0.70: revisions r0001-r0224 train, r0225-r0320 held out, of
which 37 have at least one failing test. Never a random split.

### Limitations, stated plainly

- Synthetic. Nothing here establishes how any strategy behaves on a real
  repository's history.
- The generator draws failures with probability decaying in import distance, so
  a learned model that keys on distance is partly learning the generator. The
  fitted model keys on churn instead (combined distance importance 0.0061),
  which makes the result less an artifact of the generator than it could have
  been, but does not remove the concern.
- 24 test nodes. Rank-based metrics on a 24-element order are coarse.
- Churn is drawn independently of whether a regression occurs beyond the
  declared severity term, so the churn signal the learned model leans on is as
  strong as the generator makes it and no stronger.
- No author, identity, organisational or personal attribute of any kind is
  present.
