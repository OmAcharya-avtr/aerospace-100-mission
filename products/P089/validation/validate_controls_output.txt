6.4 audit: does any assertion in the suite rest on pytest.approx's default?
==============================================================================
pytest.approx(expected, rel=r) passes if EITHER the relative or an absolute bound is met, and the absolute default is 1e-12. For a misalignment component of order 1e-5 rad, every relative tolerance tighter than 1e-7 is therefore silently replaced by the default and the assertion stops testing what it says it tests.

The audit is not a source scan. The whole suite is re-run in a subprocess with pytest.approx PATCHED so that a call carrying rel= and no abs= raises, which is the only way to find out what actually depends on the default.

    suite re-run with the default forced off, exit 1
    tests declared 307, testcase elements 307
    assertions depending on the hidden default: 1
      test_pytest_approx_absolute_default_is_never_relied_on

    The single dependent test is the deliberate demonstration in tests/test_regressions.py, which asserts BOTH branches: that a bare rel= passes on a value wrong by 1e-13 and that the same comparison with abs=0.0 does not. It is supposed to fail under this audit. No measurement in this repository rests on the default.
[PASS] exactly one assertion in the suite depends on pytest.approx's absolute default -- 1 of 307 tests, and the junit declaration agrees with its own 307 testcase elements
