# Dataset card: bitflipsim synthetic classification problem

**Summary: this dataset is synthetic, has no physical meaning, and is not
evidence about anything.** It exists so that an inference pipeline exists to
damage, and so that the degradation metric has something to degrade. None of
this product's claims depend on it being realistic, and none of them should be
read as claims about any real aerospace workload.

## 1. What it is

A three-class, eight-feature Gaussian-cluster classification problem generated
by `sklearn.datasets.make_classification` with a fixed seed, then standardised
to zero mean and unit variance using statistics fitted on the training split
alone.

| Parameter | Value |
|---|---|
| generator | `sklearn.datasets.make_classification` (scikit-learn 1.9.1) |
| `n_samples` | 1500 |
| `n_features` | 8 |
| `n_informative` | 5 |
| `n_redundant` | 1 |
| `n_repeated` | 0 |
| `n_classes` | 3 |
| `n_clusters_per_class` | 2 |
| `class_sep` | 1.4 |
| `flip_y` | 0.01 (1 % label noise) |
| `random_state` | 20261005 |
| `shuffle` | True |

## 2. Splits

Taken in order from the generated and shuffled array, so the split is a
function of the seed alone.

| Split | Samples | Purpose |
|---|---|---|
| train | 900 | fits the reference `MLPClassifier`; also fits the standardisation |
| calibration | 300 | measures the ground-truth per-bit degradation used as the learned predictor's training targets, and supplies the activation statistics used as predictor features |
| evaluation | 300 | measures the degradation every method is finally scored on, and every campaign result |

Calibration and evaluation are **disjoint**, so the metric reported for the
learned predictor is not measured on the data its targets came from. The test
suite's fixtures use a smaller instance (400 / 120 / 120) so that the suite
stays inside its compute budget; every committed number in `README.md`,
`validation/VALIDATION.md` and `MODEL_CARD.md` comes from the 900 / 300 / 300
instance.

## 3. Generation and regeneration

The data is **not committed**. It is regenerated deterministically by
`bitflipsim.datasets.make_problem()`, which takes about 0.1 s. On the same
scikit-learn and numpy versions the arrays are reproduced bit for bit; across
major versions of `make_classification` they may differ, which is why the
versions are recorded in `validation/VALIDATION.md` and in `MODEL_CARD.md` §9.

```python
from bitflipsim.datasets import make_problem, reference_parameters
problem = make_problem()                      # 900 / 300 / 300, seed 20261005
params  = reference_parameters(problem)       # 147 float32 parameters
```

## 4. The derived artefact: the reference model

The thing actually injected into is not the dataset but the model fitted on it:

| Property | Value |
|---|---|
| estimator | `sklearn.neural_network.MLPClassifier` |
| architecture | 8 -> 12 (ReLU) -> 3, softmax |
| solver | Adam, `learning_rate_init=3e-3`, `alpha=1e-3`, `tol=1e-4`, `n_iter_no_change=15`, `max_iter=3000` |
| `random_state` | 20261005 |
| iterations to convergence | 1130 (no `ConvergenceWarning`) |
| parameters | 147 float32 = 588 bytes = 4704 bit sites |
| accuracy, evaluation split | 0.970000 |
| accuracy, calibration split | 0.960000 |
| int8 quantized size | 147 bytes (4.00x smaller) |

The packed float32 parameter block is `[W1 | b1 | W2 | b2]` row-major, so
"parameter 37" and "byte 148" name the same physical thing, which is what an
upset model needs and what `MLPClassifier.coefs_` does not provide.

## 5. Limitations, which are the point of this card

* **Synthetic.** Gaussian clusters with a tuned separation. Real sensor data is
  not this, and a model fitted to it is not a flight model.
* **Tiny.** 147 parameters, 588 bytes. A real onboard model is 10^4 to 10^8
  times larger. The *direction* of the per-bit criticality result - the
  exponent field dominating the mantissa - follows from the IEEE 754 layout and
  is not a property of this dataset. The *size of the learned predictor's
  margin over the baselines* is a property of this dataset and this model, and
  nothing here establishes that it transfers.
* **One architecture.** One hidden layer, ReLU, softmax. No convolution, no
  normalisation layers, no residual connections, no attention. The criticality
  of a parameter in a layer with batch normalisation downstream would be a
  different question.
* **Balanced and clean.** Three roughly equal classes with 1 % label noise.
  Nothing here exercises class imbalance, distribution shift or adversarial
  input, all of which interact with upset tolerance.
* **The evaluation batch is 300 samples**, so an accuracy figure has a binomial
  standard error of about 0.01 at 0.97. Campaign results are reported with
  their standard errors for exactly this reason.
* **No provenance, licensing or privacy concerns**: the data is generated by a
  seeded pseudo-random number generator and contains no human subjects, no
  personal data and nothing collected from anywhere.

## 6. Intended and unintended use

**Intended.** Exercising this package's injection, criticality, prediction and
mitigation machinery end to end, deterministically, inside a one-core compute
budget.

**Not intended.** Benchmarking classifiers; comparing against published
accuracy figures; supporting any claim about how a real onboard model behaves
under radiation. For that, bring your own model and your own measured
cross-section, point `bitflipsim` at it, and read `docs/UPSET_MODEL.md` §5 for
where the model stops being valid.
