# Dataset card - `linkoutage` synthetic fading records

Every dataset in this repository is **synthetic and generated by committed
code from a fixed seed**. Nothing is committed as data: the largest array in
the repository is a PNG. There is no measured optical link data here, and the
absence is a limitation of everything built on it.

## Source

`linkoutage.channel.lognormal_amplitude_series`. The generative model is
stated in full in that module's docstring and is reproduced here because a
dataset card that hides its generator is useless.

1. Driving noise `z = numpy.random.default_rng(seed).standard_normal(n)`, drawn
   in **one** call. Drawing it in more than one call changes the stream and so
   changes the record.
2. Stationary AR(1) filter in log-amplitude:
   `rho = exp(-1 / (tau * fs))`, `x[0] = z[0]`,
   `x[n] = rho x[n-1] + sqrt(1 - rho^2) z[n]`. `x` has unit variance at every
   index, including index 0, and autocorrelation `rho^|k|`.
3. Lognormal irradiance at unit mean:
   `sigma_lnI^2 = ln(1 + SI)`, `ln I = -sigma_lnI^2 / 2 + sigma_lnI x`,
   `I = exp(ln I)`.
4. Amplitude `a = sqrt(I)`.

## What this dataset is not

* **It is not measurement.** No optical link, terminal, atmosphere or receiver
  was involved. Every number derived from it is a statement about the model,
  not about the sky.
* **It is not a complete fading model.** The AR(1) lognormal model reproduces
  the first-order irradiance distribution and an exponential autocorrelation,
  and nothing else. The real scintillation power spectrum rolls off closer to
  `f^(-8/3)` in the inertial range than the AR(1) Lorentzian does, so the
  relative weight of short and long fades is wrong by an amount this repository
  does not quantify. There is no aperture averaging, no beam wander, no
  pointing jitter, no inner or outer scale, and no receiver noise.
* **It is not valid in strong turbulence.** Above a scintillation index of
  about 1 the lognormal distribution is the wrong family; the gamma-gamma
  distribution of Al-Habash, Andrews and Phillips (2001) is the standard
  replacement and is not implemented here.
* **It has no non-stationarity.** Scintillation index and correlation time are
  constant over every record. A real link's are not constant over four
  seconds, let alone four hours, and the classifier results in particular would
  change under drift.

## Labelling

A row is positive when at least one **down-crossing** of the threshold occurs
in `(t, t + horizon]`, using the same crossing definition as every other number
in the package (`linkoutage.fade.FadeDefinitions`, default: strict comparison,
single-sample excursions counted). A fade already in progress at `t` is not by
itself a positive label; the forecaster is asked about a *new* onset, because
the one in progress is already visible to the receiver. `in_fade_now` is a
feature, so the models can condition on it.

Changing `count_single_sample_fades` to `False` would change the label set by
roughly a third, which is the same sensitivity the fade statistics show. The
labels and the published level-crossing rate therefore count the same events by
construction.

## Size, licence and regeneration

Nothing in the table above is committed. Regenerate any of it with a single
call; the largest record is 4 000 000 float64 amplitudes, about 32 MB in
memory and under half a second to generate.

```python
from linkoutage import lognormal_amplitude_series
series = lognormal_amplitude_series(2_000_000, fs_hz=1.0e6, tau_s=2.0e-4, si=0.6, seed=41)
```

`validation/regenerate_outage_model.py` writes the classifier dataset to
`validation/outage_dataset.npz` (about 3 MB) and the fitted models to
`validation/outage_models.joblib` (about 6 MB). Both are listed in
`.gitignore` and neither is tracked.

## Using your own data instead

Every function in `linkoutage.fade`, `linkoutage.distributions`,
`linkoutage.markov`, `linkoutage.features`, `linkoutage.predictors` and
`linkoutage.calibration` takes an array, not a model. A measured amplitude
record goes straight in:

```python
import numpy as np
from linkoutage import fade_statistics
amplitude = np.load("receiver_log.npy")          # or np.loadtxt(...)
print(fade_statistics(amplitude, threshold=0.35, fs_hz=2.0e6).report())
```

The two things to check first on a measured record are that the amplitude is
strictly positive (the features are logarithmic and will refuse otherwise) and
that the record has no gaps: a NaN anywhere makes every fade statistic
undefined and `fade_statistics` raises rather than silently skipping it. If the
record is quantised by an ADC, read the `strict_below` discussion in
`FadeDefinitions` first - on 8-bit data with a threshold on a code boundary the
two rules differ by 4.7 % in the level-crossing rate
(`validation/fade_definitions_output.txt`).
