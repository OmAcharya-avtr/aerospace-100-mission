  A .gitignore pattern with no leading slash matches at ANY depth: a
  bare junit.xml in a product .gitignore silently excluded a REQUIRED
  committed fixture in P060 of this mission, and a cold clone then
  failed with 17 failures and 9 errors while every local check passed.

  git is not run here -- this build is forbidden to run it -- so the
  patterns are matched directly against the deliverable paths, with the
  anchoring rule applied explicitly. A pattern beginning with '!' is a
  NEGATION and re-includes the file: 'git check-ignore' exits 0 when a
  negation pattern matches, so reading only its exit status would
  report a deliberately re-included file as ignored.
