==============================================================================
what a declaration looks like
==============================================================================

  The smallest built-in case, in full, so that a reader can see the
  format without opening a file:

    description: Two identical units in parallel with a declared beta factor. The smallest
      diagram on which the headline comparison says something.
    name: redundant pair
    root:
      beta_factor: 0.1
      items:
      - distribution:
          kind: exponential
          rate_per_hour: 2.0e-06
        kind: block
        name: unit_a
      - distribution:
          kind: exponential
          rate_per_hour: 2.0e-06
        kind: block
        name: unit_b
      kind: parallel
      label: pair

the loader rejects what it does not understand
==============================================================================

  A declaration is an artifact a reviewer has to be able to check, so an
  unknown key is an error and not a silently ignored field. These are
  the rejections, exercised here so that the messages are on record.

  unknown top-level key:
    <temporary directory>/bad.yaml: diagram does not accept ['extra']; accepted keys are ['description', 'name', 'notes', 'root']
  [PASS] unknown top-level key is rejected

  misspelled distribution parameter:
    distribution kind 'exponential' does not accept ['rate_per_hr']; accepted parameters are ['rate_per_hour']
  [PASS] misspelled distribution parameter is rejected

  unknown node kind:
    unknown node kind 'majority_voter'; expected one of ['block', 'k_of_n', 'network', 'parallel', 'series', 'shared_load', 'standby']
  [PASS] unknown node kind is rejected

  parallel group of one:
    parallel node 'parallel' has 1 item(s); redundancy over fewer than two items is not redundancy. Declare the item directly if that is what was meant.
  [PASS] parallel group of one is rejected

  standby without a switch reliability:
    standby declaration requires 'switch_reliability'. An undeclared switching reliability defaulting to 1.0 is exactly the implicit assumption this package exists to surface.
  [PASS] standby without a switch reliability is rejected

  k outside 1..n:
    k_of_n node 'k_of_n' declares k=4 with n=2. k must lie in 1..n: k=0 is certain success and k>n certain failure, and neither is a diagram.
  [PASS] k outside 1..n is rejected

  duplicate block names:
    diagram 'x' declares duplicate block names ['a']. Two different items sharing one name would share one failure probability and one importance measure, and the cut sets would be wrong. Rename them, or declare one block and reference it once.
  [PASS] duplicate block names is rejected

  beta factor on a k = n group:
    k_of_n node 'k_of_n' declares beta_factor=0.1 with k = n = 2, which is a series group and not a redundant one. A beta factor describes the correlation BETWEEN redundant items; on a group that fails when any single member fails it has no meaning, and the arithmetic makes the group look BETTER -- meas
  [PASS] beta factor on a k = n group is rejected
