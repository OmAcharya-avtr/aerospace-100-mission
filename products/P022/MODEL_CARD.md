# Model card — `cmgsteer.ml.LearnedNullMotion`

**This model is not certified for operational flight use.**

**Headline result: the classical singularity-robust inverse wins.** Over 16
held-out manoeuvres neither the learned null-motion policy nor the classical
gradient null motion produced a difference from plain SR-inverse steering whose
bootstrap 95% interval excluded zero, on any of three metrics — and the learned
policy costs 16.4× the runtime. Its held-out label regression has a negative
R². Details in §7.

Version 0.1.0. Every number below comes from
[`validation/validate_nullmotion_ml.py`](validation/validate_nullmotion_ml.py);
its raw stdout is
[`validation/nullmotion_ml_output.txt`](validation/nullmotion_ml_output.txt).

---

## 1. Problem

A four-CMG array has one degree of freedom left over after a three-axis torque
command is met: the null motion. Classical policies spend it greedily, climbing
the singularity measure `m` now. The question this model asks is whether a
policy trained to *anticipate* — to reconfigure the gimbals for the manoeuvres
about to be commanded rather than for the instant it is in — does better.

Given the current gimbal angles, array momentum, singularity measure, singular
direction and commanded torque, predict the scalar null-motion coefficient
`k` in `[-1, 1]` that a short-horizon lookahead oracle would choose. The
delivered null motion is `k * max_null_rate * n_hat(delta)`, where `n_hat` is
the unit null vector signed so that `k > 0` raises `m`.

This is behaviour cloning of a receding-horizon oracle, not reinforcement
learning: no PyTorch is available in the target environment.

## 2. Baselines

Three, all implemented, tested and validated (validations 1–4) **before** any
model was trained:

1. **Plain SR inverse, no null motion** — `cmgsteer.steering.sr_inverse_steer`
   with the adaptive robustness parameter `lam = lam0 h0² exp(-mu m / h0³)`.
   This is the baseline every difference is measured against.
2. **Classical gradient null motion** —
   `cmgsteer.nullmotion.GradientNullMotion`, `ddelta_null = k P grad(m)` with
   `P` the projector onto `null(A)` (Yoshikawa 1985; Bedrossian et al. 1990).
3. **Plain Moore-Penrose pseudo-inverse** — the unregularised inverse, included
   so the benchmark shows what a *real* difference looks like on this suite.

The generalised SR inverse (Wie, Bailey & Heiberg 2001) is also benchmarked.

## 3. Architecture

Ensemble of 5 `sklearn.neural_network.MLPRegressor`s, hidden layers `(64, 32)`,
ReLU, Adam, `alpha=1e-4`, `max_iter=400`, `early_stopping=True` with
`n_iter_no_change=15` and `validation_fraction=0.1`. Member `k` uses
`random_state = 0 + k`. Inputs are standardised by a `StandardScaler` fitted on
the training split.

**Inputs** (20 features, all dimensionless; see `cmgsteer.ml.feature_names`):

| Group | Count | Meaning |
|---|---:|---|
| `sin`/`cos` of each free gimbal angle | 8 | wrap-free encoding of the configuration |
| `h / sum(h0)` and `|h| / sum(h0)` | 4 | where the array sits in its momentum envelope |
| `m / h0_mean³`, `sigma_min / h0_mean` | 2 | how singular the state is |
| unit commanded torque, `|tau| / h0_mean` | 4 | what is being asked for |
| `cos` between `n_hat` and `grad(m)` | 1 | the signal the classical gradient policy acts on |
| `|cos|` between the singular direction and the commanded torque | 1 | whether the direction being lost is the direction being pushed |

**Output**: one scalar `k`, clipped to `[-1, 1]`.

**Uncertainty**: the standard deviation of `k` across the five members, plus
`confidence = exp(-std / reference_spread)` in `[0, 1]`, where
`reference_spread` is the mean ensemble spread on the training set.

## 4. Dataset

See [`DATASET_CARD.md`](DATASET_CARD.md). Fully synthetic, generated by
`cmgsteer.dataset.generate_policy_dataset`, deterministic in an integer seed.

- Train: 900 states, seed 1234, sampled from 20 seeded manoeuvres.
- Test: 300 states, seed 5678, sampled from a different 10 seeded manoeuvres.

The two splits come from disjoint manoeuvre suites generated by different
seeds, so no test state shares a trajectory with a training state. The 10%
`validation_fraction` scikit-learn holds out for early stopping comes from
inside the training split. The closed-loop benchmark uses a third suite
(seed 9012) that neither split touched.

Array configuration is fixed: the standard four-CMG pyramid, skew angle
`arctan(4/3)` = 53.13010235 deg, rotor momentum 1 N·m·s each. The model is tied
to it; see §9.

## 5. Training procedure

```bash
python validation/validate_nullmotion_ml.py
```

Fixed seeds throughout: dataset 1234 / 5678, benchmark 9012, bootstrap 4242,
model `random_state=0` (members 0–4). **No hyperparameter search was run** — the
architecture, the feature set, the horizon (25 steps), the candidate grid
(9 values) and the training size were chosen once to fit the compute budget, and
the first trained model is the one reported.

## 6. Compute

2 x86-64 CPU cores, no GPU. Python 3.11.15, numpy 2.4.4, scipy 1.17.1,
scikit-learn 1.8.0.

| Step | Wall clock |
|---|---:|
| Training-set generation (900 states × 10 rollouts × 25 steps) | 30.31 s |
| Test-set generation (300 states) | 8.93 s |
| Fitting 5 MLPs | 1.23 s |
| Closed-loop benchmark, 5 configurations × 16 × 900 steps | 82.6 s |
| **Total script** | **125 s** |

Budget for this product is 180 s. Dataset generation dominates, which is why
`cmgsteer._fast.FastStepper` exists: it fuses the three singular value
decompositions of the public code path into one and is 5.35× faster, verified
identical to 1e-15 in `tests/test_dataset.py::TestFastStepperAgreement`.

## 7. Metrics — measured, as they came out

### 7a. The oracle's own headroom

Before asking whether the model learns the oracle, it is worth asking how much
the oracle is worth. With 25 steps of perfect foresight:

| Split | `k = 0` (plain SR) | Best candidate | Classical gradient | Oracle gain |
|---|---:|---:|---:|---:|
| train (900) | 1.301202e-02 | 1.006399e-02 | 1.193082e-02 | 22.66% |
| test (300) | 2.502476e-02 | 1.922236e-02 | 2.279211e-02 | 23.19% |

**A clairvoyant null-motion policy is worth about 23% of the horizon momentum
error.** That is the ceiling for any policy of this shape, and it bounds
everything below.

### 7b. Held-out label accuracy

| Quantity | Value |
|---|---:|
| Mean absolute error | 0.492465 |
| RMS error | 0.623504 |
| Label standard deviation | 0.596145 |
| **R²** | **−0.093894** |
| Sign agreement with the oracle label | 0.5833 |
| Predicted mean, std | +0.1292, 0.2976 |

**The regression is worse than predicting the training mean.** The oracle label
is a function of the next 25 commanded torques, which the policy's features do
not contain and cannot contain; a large part of the label is therefore
unpredictable in principle from the observed state, and the model hedges toward
the mean (predicted std 0.298 against a label std 0.596) while still doing worse
than the mean because of what variance it does emit. 18.3% of the training
labels sit at a grid edge (`|k| > 0.99`), so the target is partly a saturated
bang-bang decision that a squared-error regression handles badly.

### 7c. Oracle gap at the predicted coefficient

Scoring the *predicted* `k` on the same horizon objective, by linear
interpolation on the candidate grid:

| Quantity | Value |
|---|---:|
| Mean horizon score at the predicted `k` | 2.241476e-02 N·m·s |
| Mean horizon score at `k = 0` | 2.502476e-02 N·m·s |
| Mean horizon score at the oracle `k` | 1.922236e-02 N·m·s |
| **Fraction of the oracle gain captured** | **44.98%** |
| States where the policy is worse than `k = 0` | **52.33%** |

A negative R² and 45% of the available gain are consistent because the objective
is flat near its optimum: a badly chosen coefficient often costs little, and the
mean gain comes from a minority of states where the choice matters. It is also
worse than doing nothing on more than half of individual states.

### 7d. Closed-loop benchmark — the number that decides it

16 held-out manoeuvres (seed 9012) of 900 steps each, `dt` 0.02 s, gimbal-rate
limit 2 rad/s.

| Configuration | Path err [N·m·s] | Net err [N·m·s] | Min `m` | RMS tau err [N·m] | Saturated steps |
|---|---:|---:|---:|---:|---:|
| pinv | 7.371954e-01 | 2.900413e-01 | 0.256271 | 1.818783e-01 | 30.94 |
| **sr** | **4.921487e-01** | **2.181053e-01** | 0.260340 | 1.141659e-01 | 22.94 |
| gsr | 4.920096e-01 | 2.192314e-01 | 0.260342 | 1.140798e-01 | 22.94 |
| sr+grad | 4.571102e-01 | 3.025358e-01 | 0.234056 | 1.168396e-01 | 18.00 |
| sr+learned | 4.793887e-01 | 2.926328e-01 | 0.230814 | 1.142026e-01 | 20.06 |

resamples:

|---|---|---:|---|---|
| pinv | path | +2.450466e-01 | [+7.7848e-02, +4.4834e-01] | **worse than SR** |

In point estimates the learned policy reduces the path momentum error by 2.59%
and the gradient policy by 7.12%; both raise the net momentum error (by 34% and
39%) and both lower the minimum singularity measure reached. **Not one of those
six differences has an interval excluding zero.** The only distinguishable
difference in the whole benchmark is that the plain pseudo-inverse is worse than
the SR inverse — which is the classical result, reproduced.

### 7e. Runtime

| Configuration | µs per step | vs SR |
|---|---:|---:|
| pinv | 271.2 | 1.05× |
| sr | 258.3 | 1.00× |
| gsr | 265.1 | 1.03× |
| sr+grad | 707.6 | 2.74× |
| sr+learned | 4233.1 | **16.39×** |

Five scikit-learn `predict` calls on a single sample dominate the learned
policy's cost, and a sequential control loop cannot batch them.

## 8. Uncertainty output

| Quantity | Value |
|---|---:|
| Pearson r(confidence, \|label error\|) | **−0.1661** |
| Pearson r(ensemble spread, \|label error\|) | +0.1599 |
| Mean ensemble spread / rms label error | **0.2870** |

Mean absolute label error by confidence decile, lowest confidence first:
0.6332, 0.5122, 0.4799, 0.5894, 0.4500, 0.5152, 0.5294, 0.4405, 0.4140, 0.3609.
The normalised oracle gap by the same deciles: 0.2185, 0.5237, 0.4761, 0.3853,
0.3692, 0.2517, 0.2067, 0.3207, 0.4120, 0.2710.

**The confidence output is not usable.** The label-error trend is downward but
non-monotone and the correlation is weak (r = −0.17, so confidence explains
under 3% of the variance in the label error); the oracle-gap ordering
is not monotone in any direction. The ensemble spread is 0.287 of the rms error,
so it understates the error by roughly 71% and must never be used as a variance
in a filter or a control loop. `confidence_floor` exists in the API as a
fallback hook and is `None` by default, precisely so that the raw model is what
gets benchmarked; on this evidence it should not be relied on to catch bad
predictions.

## 9. Failure cases

- **It does not distinguishably beat doing nothing** (§7d). That is the
  principal failure case and it is the reason this model is documentation
  rather than a recommended component.
- **Negative R² on the held-out labels** (§7b). The target is partly
  unpredictable from the state, and the model is worse than the mean predictor.
- **Worse than `k = 0` on 52% of individual states** (§7c), even where it is
  better in the mean.
- **The confidence output does not identify those states** (§8).
- **Silent geometry mismatch.** The model is bound to the standard four-CMG
  pyramid with unit rotor momenta. Applied to a different array with four free
  gimbals it returns a confidently wrong coefficient with no exception; only the
  feature *count* is checked.
- **No null space, no action.** At an exact singularity `null(A)` is
  two-dimensional and `unit_null_vector` raises; `LearnedNullMotion.act` then
  returns zero rates. The policy therefore does nothing at exactly the
  configurations that motivate it.
- **Arrays with more than four free gimbals are out of scope.** A scalar
  coefficient cannot describe a null space of dimension greater than one.
- **A locked gimbal is not represented.** The feature vector's length depends on
  the number of free gimbals, so a model trained on a healthy array cannot be
  applied after a CMG failure at all.
- **Extrapolation.** Training manoeuvres store 35–65% of the array's momentum
  capacity in pulses of 6 s. Nothing is known about slower, faster, larger or
  sustained-hold commands.
- **The rate limit was fixed at 2 rad/s** in both training and benchmark. A
  different limit changes which states matter and was not tested.

## 10. Ethical and safety limits

Research-grade software. Not flight-qualified, not certified, not approved for
operational aerospace use. No DO-178C, ECSS-E-ST-40C or equivalent process was
followed and there is no independent verification.

**This model is not certified for operational flight use.** It must not be
placed in a spacecraft CMG steering path. On the evidence above, the plain
singularity-robust inverse is indistinguishable from it in accuracy and 16×
cheaper, so there is no operating point on this problem where the learned policy
is the right engineering choice.

Its legitimate uses are as a research baseline for anyone attempting a better
learned null-motion policy — the oracle headroom of 23% in §7a is the number to
beat, and the dataset generator is committed — and as a measured counterexample
to the assumption that a learned reconfiguration policy must beat a greedy
classical one.

## 11. Reproducibility

```bash
pip install -e ".[test]"
python validation/validate_nullmotion_ml.py    # ~125 s on 2 cores
python examples/learned_null_motion.py         # reduced-size figure, ~63 s
```

Seeds: training data 1234, test data 5678, benchmark suite 9012, bootstrap
4242, model `random_state=0` (members 0–4). All randomness goes through
`numpy.random.default_rng` and scikit-learn's `random_state`, so a run on the
same numpy / scikit-learn / BLAS build reproduces these digits. Last digits may
move on a different BLAS; the conclusions do not — they rest on confidence
intervals several times wider than any plausible numerical drift.
