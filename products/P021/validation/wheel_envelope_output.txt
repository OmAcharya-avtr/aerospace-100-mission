PART A -- zonotope facet formula against linear programming
==============================================================================
cap(u) = max{t >= 0 : t u = A c, |c_i| <= bound} is a linear programme.
Because {A c : |c| <= bound} is a zonotope, every facet is spanned by a
pair of generators, so cap(u) = min_f bound h_f / |u . n_f| with
n_f = a_i x a_j normalised and h_f = sum_k |a_k . n_f|. The two routes
share no code: one is HiGHS simplex, the other is six dot products.

PART C -- the minimum-norm allocation is a lower bound on the envelope
==============================================================================
The planner sizes against the minimum-norm allocation, because that is
what a controller using a plain pseudo-inverse delivers. The exact
envelope is larger, and the ratio below is the headroom a bounded
allocator (AllocLab, P023) would recover. It is reported, not assumed.

==============================================================================
PART E -- a failed wheel
==============================================================================
Removing one wheel from the pyramid leaves a rank-3 array with a much
smaller envelope. The capability along each body axis, before and after:

rank full 3, rank reduced 3
direction       full [N*m]    3 wheels [N*m]     ratio
+x                0.244949          0.122474    0.5000
+y                0.244949          0.244949    1.0000
+z                0.346410          0.173205    0.5000
-x                0.244949          0.122474    0.5000
(1,1,1)           0.248528          0.124264    0.5000

worst-direction capability: full 0.244988 N*m, 3 wheels 0.122494 N*m (50.00 %)
The array is still rank 3, so no direction is unreachable, but the loss
is strongly direction-dependent: exactly half along x, y and z but none
along +y, where the surviving wheels already did all the work. That is
why the planner sizes each segment against the direction that segment
actually needs rather than against a single scalar torque budget.
