the positive control: the choke point does grant a label
==============================================================================
A check that only ever observes refusals cannot distinguish a working
invariant from a function that raises unconditionally. These three must
SUCCEED, and a failure here is as much a defect as a successful attack.

[PASS] the simulated label is GRANTED by the choke point -- SYNTHETIC
[PASS] the recorded label is GRANTED by the choke point -- REPLAYED
[PASS] the live label is GRANTED by the choke point -- MEASURED

The MEASURED row is granted on a LIVE clock reading, and its headline

this host by construction and not by discipline.

==============================================================================
the two routes that SUCCEEDED, and what was changed
==============================================================================
Route 10, dataclasses.replace. Found on 2026-11-11. The exact attack:

    laundered = dataclasses.replace(simulated_reading, provenance=LIVE)
    certify('figure', attribute([laundered]), Label.MEASURED, platform)

`dataclasses.replace` is public API on every dataclass. It re-ran the
Reading's __post_init__, which RECOMPUTED THE SEAL, so the laundered
reading was validly sealed, carried the simulated reading's own channel
and value, and claimed LIVE. The choke point granted MEASURED. One line,
no private state touched. The seal did not help, because the seal was
recomputed by the very mechanism being abused.

THE FIX WAS TO THE DESIGN. A Reading's first field is now a
dataclasses.InitVar holding a module-private minting token, so
`dataclasses.replace` and `copy.replace` both raise and the single
minting entry point is boardprobe.readings.mint(), whose only in-package
callers are Source.read() and from_mapping(). The route is pinned as a
regression test in tests/test_readings.py.

Route 13, rebinding the class attribute. Found the same day. Provenance
was read from `type(self).backend_provenance`, which is an ordinary class
attribute and can be assigned to. THE FIX: the three backends' declared
provenances are captured in a module-private registry when
boardprobe.sources finishes importing, and the property compares the
class attribute against the registry on every read.

==============================================================================
what is NOT closed, named rather than omitted
==============================================================================
Three things, and none of them is a route from an EXISTING simulated
reading to a measured label, which is what this check is about.

  a. boardprobe.readings.mint() lets its caller choose a provenance. A
     caller who passes LIVE for a generated number has made a false
     statement at the source. No type system can prevent that; a
     hardware abstraction layer is a program that believes the kernel.
     What changed is that the false statement is now made in ONE named
     function, is attributable to a source_id that travels with the
     reading, and cannot be made by accident or by a refactor.
  b. A PlatformAttestation can be constructed by hand with
     matches_target=True. That is a false claim about WHICH machine, not
     about provenance, and every certificate records the attestation's
     own `source` string so the claim is legible in the output.
  c. Code running in this process can reach into module-private state
     (boardprobe.readings._KEY, boardprobe.sources._SEALED and
     _DECLARED) and defeat all of the above. This is true of every
     Python program and is stated rather than papered over.
