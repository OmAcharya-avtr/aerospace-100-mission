==============================================================================
3. this script pollutes nothing, and nothing polluting is tracked
==============================================================================
Two distinct claims, because they have two distinct owners.

An earlier revision of this script asserted that NO cache directory and no
bytecode file existed anywhere in the tree at the moment it ran. That claim
is not this product's to make, and it is unsatisfiable under the release
gate: the gate runs `ruff check src/ tests/` with its working directory set
to the product root as check 2, which writes `.ruff_cache` into the tree,
and then re-executes this script as check 6, which failed on the directory
the gate itself had just created. No change to this product could have
passed. Measured 2026-11-02 by running the two steps in the gate's own
order. The gate already prevents the identical pytest side effect with
`-p no:cacheprovider`; the ruff case is the same omission and is reported
to the owner rather than patched here, because this product does not edit
the gate that judges it.

The two claims below are what this product can be held to, and both are
stricter than the old one in the direction that matters: the old check
said nothing at all about what is TRACKED, which is the only thing a
reader with a cold clone ever sees.
