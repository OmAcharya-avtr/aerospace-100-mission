7. Label composition
==============================================================================
subset                                                  rows  positives     rate
--------------------------------------------------------------------------------
all requests                                            2903        895   0.3083
capacity_deficit > 0 (asked for more than its passes allow)     604        604   1.0000
capacity_deficit <= 0 (lost the contention, or won)     2299        291   0.1266

The first subset is trivially predictable: a request asking for more contacts
than its own passes can carry is unsatisfiable whatever the competition does,
and the feature capacity_deficit says so directly. Those rows are kept because
they are a real part of the label, and every model score in
validate_predictors_output.txt is reported BOTH over all requests and over the
hard subset, because reporting only the first would flatter every model.
