The two per-bin ratios the specification names, ratio_max and ratio_weighted,
are the weakest of the three over the whole test set. The per-request ratio
demand_over_usable is the strongest and is therefore the baseline the learned

itself informative: the per-bin ratios carry more signal once the trivially
over-asked requests are removed.

4. The verdict, as measured
==============================================================================
The learned model is compared against the BEST baseline on each metric
separately, not against one nominated baseline. On this test set the ranking
and logistic forms of demand_over_usable tie on area under the ROC curve but
the ranking form has the lower Brier score, so nominating the logistic form
as the single baseline would have handed the learned model an easier Brier
comparison than the baselines actually offer.

metric                                      best baseline   baseline    learned     margin
--------------------------------------------------------------------------------------------
roc_auc                       ranking[demand_over_usable]   0.922952   0.984596  +0.061644
average_precision             ranking[demand_over_usable]   0.885048   0.969138  +0.084090
brier                         ranking[demand_over_usable]   0.098911   0.046725  +0.052185
ece                          logistic[demand_over_usable]   0.012237   0.027302  -0.015065
f1                            ranking[demand_over_usable]   0.733728   0.886256  +0.152528
auc_hard                          ranking[ratio_weighted]   0.838021   0.952907  +0.114887

Margin is signed so that positive always means the learned model is better.

The baseline WINS on: ece.
That result stands. The learned model is not removed, retuned or re-split
to change it, and the metrics it loses on are listed here first.

What it costs. The learned model uses twenty-three pre-scheduling features,
needs a labelled training set built by running the exact solver on every
training instance (23 s for 320 instances here), and takes a fit
(45.6 s). The strongest baseline uses one feature, needs no
training data at all, and is a single division. A reader who cannot build a
labelled set should use demand_over_usable and expect the numbers in the row
above.

What this is NOT evidence of: skill on any real ground-station network. The
training and test instances come from one synthetic generator whose
distributional choices are printed in validate_dataset_output.txt. A reader
whose request mix differs from those choices should expect different numbers
and should re-measure.
