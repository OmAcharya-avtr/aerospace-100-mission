# Dataset card -- scenariocov fixtures 0.1.0

Everything in `fixtures/` is **synthetic**. It is not a record of any real
verification campaign, any real spacecraft or any real test programme, and no
number measured on it is evidence about a real system. It is shaped like a
close-range rendezvous verification campaign so that the measures this package
implements have something realistic to run on.

`validation/validate_fixtures_output.txt`.

## Source

Generated by `python fixtures/regenerate_fixtures.py` at seed **20261016**
using `numpy.random.default_rng`. Re-running the script reproduces every file
byte for byte on the same numpy version. There is no external data source, no
scraped data, no personal data and no third-party licensed content.

## The scenario space

| parameter | kind | levels | units | bin edges or level set |
|---|---|---|---|---|
| `closing_speed` | continuous | 4 | m/s | 0.01, 0.05, 0.10, 0.20, 0.50 |
| `range_at_handover` | continuous | 4 | m | 20, 50, 100, 200, 400 |
| `target_tumble_rate` | continuous | 3 | deg/s | 0.0, 0.5, 2.0, 5.0 |
| `nav_position_error` | continuous | 3 | m, 1-sigma | 0.0, 0.1, 0.5, 2.0 |
| `lighting` | categorical | 3 | - | full_sun, terminator, eclipse |
| `sensor_mode` | categorical | 3 | - | lidar_only, camera_only, fused |
| `thruster_health` | categorical | 3 | - | nominal, one_degraded, one_failed |

Fully crossed discretised space: 3888 combinations. `|T_1|` = 23,
`|T_2|` = 226, `|T_3|` = 1230.

The ranges are **declared fixture values, not engineering data**. They are
plausible for a small servicing vehicle in close-range operations and no
source is claimed for them, because none exists: inventing a citation for a
made-up number would be worse than saying it is made up.

## How the campaign was generated

Three phases, every draw rejected if it falls in a planted gap:

1. **60 nominal-weighted scenarios** -- slow, close, well lit, healthy
   thrusters. This is what a real campaign accumulates first.
2. **A coverage fill** -- uniform draws over the declared intervals, accepted
   only while they add a new 2-way tuple, so that every tuple except the
   planted ones is covered.
3. **A stratified tail up to 240** -- a level chosen uniformly per parameter
   and then a value uniform inside that bin, which makes the grid cells
   equiprobable. Phase 2 draws uniformly in *value*, which makes wide bins far
   more likely than narrow ones; the two rules are kept separate in the
   generator so the difference is deliberate rather than accidental.

The candidate pool is 400 uniform draws over the declared intervals and level
sets with the planted regions **included**, so that every strategy in the
benchmark is able to reach the gaps.

Continuous values are rounded to 3 or 4 decimals before writing. One
consequence is visible and deliberate: record 191 has `nav_position_error`
exactly 0.1, which is an internal bin edge, and
`ScenarioSpace.edge_ambiguities` reports it.

## The five planted gaps

| id | rule | the measure that is supposed to find it |
|---|---|---|
| G1 | `lighting == eclipse AND closing_speed >= 0.20 m/s` | 2-way tuple |
| G2 | `thruster_health == one_failed AND sensor_mode == camera_only` | 2-way tuple |
| G3 | `closing_speed >= 0.20 m/s AND range_at_handover >= 200 m` | 2-way tuple, and 9 empty grid cells |
| G4 | `nav_position_error >= 1.5 m` | the declared class `nav_position_error/excessive` |
| G5 | `abs(range_at_handover - 200 m) <= 2.5 m` | the declared boundary `handover_200m`, tolerance 2.0 m |

G4 and G5 sit inside a single declared bin and are therefore **invisible to
the combinatorial measures by construction**. That is the reason the fixture
carries them: a package with only t-way coverage would report this campaign as
0.986726 covered and say nothing about either.

Measured on the committed files: 2-way coverage 223/226 = 0.986726 with
exactly the three planted tuples uncovered and **no false positives**; class
coverage 14/15 with exactly G4 uncovered; grid occupancy 108/144 = 0.750000
with all 9 cells of the G3 region empty.

## One thing the fixture produced that was not planted

The declared boundary `target_tumble_rate/tumble_limit_2p0` is missed, with a
nearest approach of 0.021 deg/s against a declared tolerance of 0.020 deg/s --
a margin of -0.001 deg/s. This was not designed; it fell out of the seed. It
is kept because it is the clearest possible illustration of why every boundary
result in this package reports the nearest distance beside the hit flag.

## Limitations

1. Synthetic throughout. Nothing here establishes behaviour on a real
   campaign.
2. The holes are deliberate, contiguous and large. Real coverage gaps are
   usually accidental, scattered and smaller, and are harder to find than
   these.
3. The parameters are independent by construction. A real scenario space has
   correlations and forbidden combinations, and this package has no way to
   declare either.
4. 240 scenarios over 3888 discretised combinations is a thin campaign. It is
   thin on purpose, because a campaign with no gaps would make a poor fixture
   for a gap finder.
5. The generator depends on `numpy.random.default_rng` stream stability. The
   committed files were produced with numpy 2.5.3 and are identical under
   numpy 2.3.4 (`validation/validate_dependency_ends_output.txt`); a future
   numpy that changed the generator stream would reproduce different files
   from the same seed, which is why the files are committed rather than
   generated at test time.
