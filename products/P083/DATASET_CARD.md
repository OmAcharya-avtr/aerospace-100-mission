# Dataset card — `hilverdict` synthetic hardware-in-the-loop runs

**Product:** P083 `hilverdict` · **Version:** 0.1.0

Every dataset in this repository is **synthetic and generated by committed
code**. No measurement of any real rig, flight computer, bus, actuator or test
article appears anywhere in it. No data file is committed: every run is
regenerated deterministically from a declared seed by the script that uses it,
so the repository carries the generator rather than the data.

## What one record is

One **run**: a miss-free reference trajectory of 200 controller iterations at
10 ms, the commanded-incidence schedule that produced it, a measured
execution-time trace of the same length, and paired host and device timestamps
at every sample instant. From a run, `hilverdict.timeline.miss_events` derives
one **miss event** per iteration whose execution time exceeded the declared
deadline, and each miss event is one row of the learned component's dataset.

## How a run is generated

`hilverdict.synthetic.generate_run(seed, profile, amplitude_deg, steps, clock)`.

**The trajectory.** The declared two-state short-period plant of
`hilverdict.plant`, equations (1)-(2), under the declared sampled regulator of
equation (3), integrated with fixed-step fourth-order Runge-Kutta at 4
substeps per period. The commanded incidence is a square wave through six
declared switch fractions — `0.10, 0.25, 0.40, 0.55, 0.70, 0.85` of the run —
at levels `0, +1, -1, +1, -0.5, +0.5, 0` times the amplitude. Six switches
rather than one, because a held command only matters when the command was
going to change and a schedule with one transient would make the whole study a
study of one transient.

**The execution times**, equations (17)-(18): a lognormal body plus Bernoulli
stalls,

```
d_k = T f exp(sigma Z_k) + S_k,   Z_k ~ Normal(0, 1)
S_k = B_k E_k,  B_k ~ Bernoulli(p),  E_k ~ Exponential(mean = s T)
```

with the `bursty` profile additionally correlating `B_k` so that a stall
starts a geometric run of them. Three declared profiles:

| profile | `f` | `sigma` | `p` | `s` | burst continuation |
| --- | --- | --- | --- | --- | --- |
| `nominal` | 0.60 | 0.30 | 0.050 | 0.8 | 0.00 |
| `loaded` | 0.82 | 0.16 | 0.035 | 1.1 | 0.00 |
| `bursty` | 0.60 | 0.26 | 0.040 | 1.4 | 0.50 |

**The clocks**, equation (19): the host series is the exact sample grid by
declaration; the device series carries a constant relative rate error in parts
per million, additive Gaussian jitter, quantisation to a declared tick, and
zero or more resets at declared fractions of the run. **The recorded durations
are device-measured**, so a device clock running fast by `rho` reports every
interval as `1 + rho` times its true length — which is the coupling that makes
the clock check part of the timing verdict rather than a side report.

## Declared campaigns

Nine, cycled across a population so every shape appears: three timing profiles
crossed with manoeuvre amplitudes of 3, 6 and 8 degrees. Measured peak
incidence 1.0592 to 2.7959 deg against a declared validity limit of 10 deg,
peak command 13.3302 to 35.1840 deg against an actuator limit of 40 deg, and
**0 saturated iterations** on all nine — so every declared campaign is
admissible to the certificate. Verified in
`validation/validate_plant_output.txt` section 6.

| learned-component test | 2000-2044 | 45 | 841 | 47 | 0.055886 |

All three seed ranges are disjoint. **The learned split is by RUN, never by
miss**: misses inside one run share its trajectory and its timing trace and are
not independent of each other.

The example scripts use their own disjoint seed ranges (8000-8035, 8100-8126,
8200-8253, 8300-8335, 8400-8408, 8500-8517) so that no figure is drawn on the
data a reported score was measured on.

## Labels

A miss is **consequential** when the re-simulated peak divergence between the
with-miss and the miss-free trajectory reaches the declared tolerance of 1 in
the declared metric. The label comes from `hilverdict.resimulate`, baseline 2,
and from nothing else: no label in this repository is produced by a bound, a
heuristic or a prediction.

The label is a threshold comparison on a number the integrator produces, so
its stability under the integrator's own step size is measured rather than
assumed: **0 verdict flips** between the declared 4 substeps and 16, with the
worst step-size shift at **5.416102e-08** of a miss's own distance from the
tolerance (`validation/validate_resimulation_output.txt` section 3).

## Class balance

5.6 to 7.2 per cent consequential. That is a deliberate property of the
generator and not an accident: the product exists because most deadline misses
do not matter, and a dataset in which half of them did would not pose the
problem the product is about. It is also the reason accuracy is not reported
anywhere in this repository.

## Known limitations of the data

- **It is a fiction.** The plant's coefficients, the execution-time model and
  the clock model are all declared, with an engineering shape and no fit to
  any measurement. Nothing measured on this data establishes behaviour on a
  real log.
- **The execution times are independent of the trajectory.** A real loop's
  execution time depends on what the software is doing, and a control law
  whose branch structure depends on the state would correlate the two. Here it
  does not, which makes the timing trace and the manoeuvre independent in a way
  a real rig's are not.
- **The miss model does not cascade.** The generator produces execution times
  freely; the consequence model holds the last value and does not push the next
  iteration late. The cascade count is 2 to 3 times the direct count on a
  loaded run, and is reported on every run.
- **One plant, one controller, one metric.** Every number in this repository
  is measured on the same declared loop. The anisotropy sweep in
  `validate_certificate.py` varies the metric and nothing varies the plant.
- **No sensor noise, no quantisation of the control, no actuator dynamics.**
  The only non-ideality modelled is timing, which is the subject; everything
  else is exact, and a real rig's divergence would contain terms this data has
  none of.
- **The clock jitter is Gaussian and the drift is constant.** A real crystal's
  rate wanders with temperature, which this model has nothing of.

## Regeneration

Deterministic from the declared seeds on any machine with the same numpy
generator:

```python
from hilverdict import generate_population, generate_run

log = generate_run(seed=902, profile="loaded", amplitude_deg=8.0, steps=200)
runs = generate_population(tuple(range(2000, 2045)), steps=200)
```

Nothing is cached and nothing is committed. Regenerating the labels for all
2256 misses of the learned study takes **4.40 s** on two cores, 2.79 s for the
72 training runs and 1.61 s for the 45 test runs, both printed in
`validation/validate_learned_model_output.txt`. That figure moves by tens of
per cent between runs on shared hardware; the plant-evaluation counts beside
it do not.
