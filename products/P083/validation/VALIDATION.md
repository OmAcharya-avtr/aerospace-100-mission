# Validation

**Product:** P083 `hilverdict` · **Validation level:** Level 3 · **Status:** TESTING ·
**Class:** medium · **AI:** yes

Every number on this page was produced by a script in this directory, run in
the session that wrote the page, on the environment recorded in the header of
each output file. The raw output of each script is committed beside it as
`<script-name>_output.txt`. Nothing here is quoted from a reference work, a
changelog or an earlier run.

Every number is measured against **synthetic** hardware-in-the-loop runs
generated by `hilverdict.synthetic` from the declared plant of
`hilverdict.plant`. No measurement of any real rig, flight computer, bus or
test article appears anywhere in this repository. The purpose of the
synthetic generator is to make the TRUE consequence of each deadline miss
knowable by re-simulation, so that a dismissal can be scored on whether it was
actually safe rather than on whether it looks reasonable.

## What is being validated

A verdict about a hardware-in-the-loop run is a claim about a **declared
model**: a plant, a controller, a sampling law and a divergence metric. This
page establishes, in order, that each declared object is what it claims to be;
that the closed-form certificate of equation (13) is a correct consequence of
them; that it is never violated by the nonlinear reference over a population
the learned comparison never sees; that it disposes of most misses without
dismissing a single consequential one; and that the learned component, given
every number the proof uses and twelve more besides, loses.

### The integrator floor

A miss whose input step is exactly zero injects nothing, so its true
divergence is exactly zero -- but the with-miss branch integrates the affected
period in two pieces while the reference integrates it in one, and two
fixed-step Runge-Kutta integrations of the same interval with different
substep layouts do not agree to the last bit. Measured:

| substeps | worst zero-input divergence |
| --- | --- |
| 2 | 3.851159e-08 |
| **4 (declared)** | **2.396608e-09** |
| 8 | 1.494631e-10 |
| 16 | 9.331158e-12 |

The ratios between successive rows are **16.0692, 16.0348, 16.0176**, which is
the fourth-order behaviour the integrator advertises. The declared floor is
2.396608e-09, which is 2.4e-09 of the declared tolerance, and it is added to
every bound before the soundness comparison of section 3. Three misses in the
first population measured during this build had a bound of exactly zero and a
re-simulated divergence of about 2e-10 for this reason alone; the floor is the
honest account of that and is measured by a function both
`validate_plant.py` and `validate_certificate.py` call, so the two quote the
same number.

### Reported, not controlled

A certificate built at an operating point 10 degrees away from the one the run

the bound larger. A mis-declared operating point is therefore dangerous in the
other direction -- declaring a high-incidence run at the origin -- which is the
direction the incidence refusal guards.

## What this validation does NOT establish

- **Nothing here is measured against hardware.** There is no rig, no flight
  computer and no test article in this repository. The plant's coefficients
  are a declared fiction with an engineering shape.
- **The certificate is a theorem about the declared linearisation.** Section 3
  measures that the linearisation covers the declared nonlinear plant in the
  declared region over 875 misses. It does not prove it, and no finite
  population could.
- **The analysis is one miss at a time.** Section 7 measures the aggregate
  bound and the all-misses divergence, which is the only statement made about
  interactions.
- **The miss model does not cascade.** The cascade overrun count is reported
  beside the direct one on every run and is 2 to 3 times larger on a loaded
  run; a run whose cascade count greatly exceeds its direct count is outside
  what the verdict covers.
- **Dependency ranges were measured at one version each**, except `ruff`,
  which was measured at both ends. The build environment is a shared pre-pinned
  interpreter this product is forbidden to modify.
