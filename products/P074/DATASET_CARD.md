# Dataset card — orbitdrift divergence dataset

Two files are committed:

| File | Size | Contents |
|---|---|---|
| `fixtures/population.tle` | 32247 bytes | 192 two-line element sets, with a comment line per object giving its epoch group |
| `fixtures/divergence_dataset.npz` | 217505 bytes | the divergence table: 5376 rows x 17 columns, plus the column names, the TLE text and the provenance string |

Both are regenerated by `python validation/regenerate_dataset.py`, which takes
about three minutes on two cores. `validation/validate_reproducibility.py`
checks that the population reproduces byte for byte from its seed
(sha256 `c1a862cbc73c58bc7b2c461f34aea5b58babba375888cf12cc18fbc95abfa90a`).

## 1. What this dataset is not

**It is not a sample of the real catalogue.** There is no two-line element
archive in this environment. The population is synthetic, drawn from declared
distributions with a fixed seed, and each feature is drawn **independently** of
the others.

That makes it a spanning set over feature space, which is what a benchmark over
feature space needs, and it is **not** a representation of the catalogue's joint
distribution. A real population has `B*` strongly correlated with altitude and
with area-to-mass class; this one does not, deliberately, so that the benchmark
can separate the effect of altitude from the effect of the drag parameter. The
correlation of fitted growth exponent with the drag parameter (+0.5090) is
measurable *because* the two were decoupled.

Any conclusion of the form "x per cent of catalogued objects behave like this"
cannot be drawn from this dataset. Conclusions of the form "a model that sees
these features predicts this well on held-out objects" can.

### Why negative `B*` is in the population

A negative `B*` is a legal two-line element set and occurs in the public
catalogue for objects whose semi-major axis was observed to rise. It makes the
drag term an along-track thrust. `orbitdrift.forces.cd_area_over_mass_m2_kg`
passes it through unchanged rather than clipping it to zero, because clipping
would silently change the dynamics of the object the user supplied, and
`tests/test_forces.py` asserts that the resulting acceleration has positive
power. Six objects exercise that path.

### The eccentricity cap, and why it is there

The population is capped near `e = 0.05`. A fixed-step integrator is a poor fit
to an eccentric orbit: the perigee passage is fast and the apogee arc is slow,
so a step chosen per revolution is far too coarse at perigee. Measured in
`validation/validate_kepler_reference.py`: at 1440 steps per revolution the
relative position error is 5.004e-10 at `e = 0.001`, 6.201e-10 at `e = 0.06`
and 1.014e-06 at `e = 0.59`. The cap keeps the dataset inside the regime where
the integrator's error is three orders below the divergence being measured.

## 3. Every orbit is a real two-line element set

The drawn mean elements are fed to `Satrec.sgp4init` and then written out with
`sgp4.exporter.export_tle`, and the committed `fixtures/population.tle` is
re-read through `Satrec.twoline2rv` before use.

The round trip through the fixed-width TLE format **quantises every element**:
eccentricity to seven decimal places, mean motion to eight, `B*` to five
significant figures. The quantised values are what everything downstream sees. A
population held in floating point and never written to a TLE would be a
population no operator could ever have, and the quantisation is part of what the
product has to work with.

`orbitdrift.dataset.load_population` validates each pair itself — line length,
ASCII, and the catalogue numbers matching across the two lines — because
`Satrec.twoline2rv` in the accelerated C++ build of `sgp4` 2.27 is permissive.
Measured: a truncated line 2, a line 2 belonging to a different catalogue
number, a non-ASCII character in a numeric field, and a line 1 not beginning
with `1` were all accepted without an exception and produced a silently wrong
orbit. Five such inputs were tried and none raised, so the checks in
`load_population` are the only checks there are.

## 4. The divergence table

One row per (object, epoch age). 17 columns, in this order:

| Column | Units | Notes |
|---|---|---|
| `object_index` | — | position in the TLE file |
| `epoch_group` | — | 0, 1 or 2 |
| `perigee_altitude_km` ... `log10_drag_parameter` | see `MODEL_CARD.md` §4 | the ten static features |
| `epoch_age_days` | days | from half an orbital period to 6.7933 days |
| `drift_km` | km | the window-RMS separation |
| `drift_radial_km`, `drift_in_track_km`, `drift_cross_track_km` | km | window RMS of the absolute components in the reference state's RIC frame |

Provenance string stored in the file:

```
reference period of 5465.029821 s at 360 steps per revolution, 39840 steps,
reported every 6.0 h, drift is the RMS over a one-period window; force model
WGS72: two-body + J2-J4 + drag + luni-solar
```

| Quantity | Value |
|---|---|
| rows | 5376 |
| objects | 192 |
| ages per object | 28 |
| `drift_km` range | 0.023069 to 3540.251 km |
| `epoch_age_days` range | 0.0316 to 6.7933 |

| rows where in-track is the largest component | 0.996466 |

### How the drift metric is defined, and why

The instantaneous separation of two propagations oscillates at the orbital
period: the radial and cross-track components are periodic and only the in-track
component grows secularly. Sampling that at an interval not commensurate with
the period aliases the oscillation into the growth curve and produces a ragged,
seed-dependent result.

The reported drift is therefore the **root-mean-square of the separation over a
window of one orbital period** centred on each reported age. The three component
columns are the window RMS of the absolute components, and they add in
quadrature to `drift_km` exactly — an algebraic identity that
`tests/test_dataset.py` checks to 1e-10.

No age inside half a window of zero is reported, because a window RMS needs a
window.

### Why the integration step is an input rather than derived

The step is `reference_period_s / steps_per_rev` with `reference_period_s`
defaulting to the shortest period in the whole file, and the value used is
recorded in the provenance string. An earlier version took the step from the
shortest period in each *epoch batch*, which made the result depend on which
other objects happened to share an epoch: recomputing three objects on their own
then differed from the committed table in the fourth significant figure. That is
the integrator's truncation floor showing through a reproducibility claim, and
the fix is to make the step a declared input.

## 5. How the dataset was computed

For each epoch group, every object's SGP4 state at its own element-set epoch
seeds one **vectorised** `orbitdrift.integrate.propagate` call: one `(64, 6)`
state array advanced 39840 fixed Runge-Kutta steps of 15.1806 s. That is what
makes the dataset affordable on two cores — the per-step Python cost is paid once
for the batch rather than once per object — and it is why objects are batched by
epoch, since the drag and third-body terms are functions of absolute time while
the integration grid is shared.

The numerical propagation is seeded from the SGP4 state at the epoch, so each
divergence curve is **zero at zero age by construction** and every later value is
accumulated disagreement rather than an initialisation offset.

Force model: WGS72 constants (the ones SGP4 itself uses, so the divergence is
attributable to model structure rather than to a constants mismatch), two-body,
`J2` to `J4` zonal, drag on the static piecewise-exponential atmosphere of
Vallado 2013 Table 8-4, and luni-solar point masses from low-precision analytic
series. Not modelled: tesseral and sectoral gravity, solar radiation pressure,
Earth albedo and infrared, solid and ocean tides, relativistic corrections.
Those omissions are part of the declared divergence.

## 6. Known limitations of the data

| Limitation | Measured consequence |
|---|---|
| the atmosphere model is static, with no solar index | published solar-cycle density variation at 400 km is about an order of magnitude; every drag-driven row sits at one unspecified point in that range |
| the `B*` inversion is an assumption | a factor of two in `C_D A/m` moves the median divergence by 0.0002 of itself and the worst object by 0.5909 |
| the integrator has a truncation floor | 1.168030e-01 km at 7 days; below 1 per cent of the divergence for three quarters of the population, above 10 per cent for 3 of 192 objects, and 18.5 per cent for the least divergent one |
| only three epochs | epoch dependence is sampled at three points eight months apart, which is enough to show the luni-solar and solar-longitude terms are not dominant and not enough to characterise a seasonal effect |
| features drawn independently | not a catalogue joint distribution; see §1 |
| the features are strongly collinear | the predictors are only valid on the manifold the population occupies; see `MODEL_CARD.md` §4 |
| 192 objects | a stratified coverage cell holds 168 to 448 rows but only about 10 to 20 objects, and the rows are grouped, so the Clopper-Pearson interval on a cell is too narrow. Both the row-level and the object-level coverage are reported |

## 7. Licence and provenance of the inputs

The population is generated by committed code in this repository and carries no
third-party licence.

The published SGP4 verification vectors used elsewhere in the validation
(`SGP4-VER.TLE` and `tcppver.out`) are **not** part of this dataset. They are
read at run time out of the installed `sgp4` 2.27 distribution as package data
and are not redistributed here.

The two real element sets for catalogue 5 in
`validation/validate_self_consistency.py` are transcribed into that script, with
their checksums recomputed and verified there. They are public two-line element
sets; the 2000 pair is the first verification case of `SGP4-VER.TLE` and the 2020
pair is the element set the same distribution carries in its test module.

The element set in `orbitdrift.__main__.DEMO_TLE` and in the worked example uses
a real catalogue number and a real orbit, but the element **values are a
plausible made-up set** and are not a real published element set for that
object. Nothing in this repository has read the catalogue.
