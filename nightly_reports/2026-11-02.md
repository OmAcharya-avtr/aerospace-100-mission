## The finding of this session: P084 was ungateable by construction

Last night recorded **one** root cause for P084's BLOCKED verdict. There are
**two**, and no change to the product could have fixed the second.

**Cause 1 — the product's own defect, correctly diagnosed last night.** The
validation scripts' own interpreter imported the package, wrote 11 `.pyc`
files into the tree, and `validate_cli.py` then scanned the tree and found
them. Fixed at cause: every entry script under `validation/` and `examples/`
now sets `sys.dont_write_bytecode` before importing anything. It cannot be
delegated to the shared `_bootstrap` module, because CPython writes a module's
bytecode cache *before* executing it, so `_bootstrap` cannot set the flag on
its own behalf. Measured: **11 `.pyc` before, 0 after.**

**Cause 2 — the harness, not previously recorded.** Release-gate check 2 runs
`ruff check src/ tests/` with its working directory set to the product root,
which writes `.ruff_cache` into the tree. Check 6 then re-executes the
validation scripts, and `validate_cli.py` asserted that **no** cache directory
existed anywhere. The gate created the condition it then failed, one check
earlier, on every run. Measured by running check 2 and check 6 in the gate's
own order on a clean tree:

```
ruff exit=0
./.ruff_cache
[FAIL] no cache or config directory exists anywhere in the tree -- 1 found
```

Had only cause 1 been fixed, tonight would have produced a second BLOCKED
verdict on the same product and would have looked exactly like last night.

**Why cause 2 stayed hidden is the transferable lesson.** Cause 1 reproduced
standalone, which is precisely why cause 2 did not: running a script by hand
from a clean tree never shows what the harness leaves behind. The general rule
is now in `PRODUCT_BUILD_GUIDE.md` — *a check whose own execution, or whose
harness's execution, can create the condition it tests is not a check.*

**The gate was not edited.** Its ruff step wants the treatment its pytest step
already has (`-p no:cacheprovider`, or a cache directory outside the tree).
That one-line change is recorded as needing the owner: an unattended session
should not edit the instrument that judges its own output. What changed is the
**scanner**, narrowed to the two claims the product actually owns — that
running it *adds* no cache artifact, and that git *tracks* none. The second is
new and is stricter than the old check in the dimension that matters, because
the old one said nothing at all about what a cold clone carries.

Fifth occurrence of the self-reporting-scanner class.

### Gate churn: inspected before reverting, and one difference not papered over

Check 6 re-executes every validation script and rewrote 13 committed output
files. **Twelve differ only in wall-clock timing.** P083's resimulation output
keeps identical miss counts (13, 15, 19, 23, 29, 29) and identical
plant-evaluation counts (17904, 25072, 26112, 45024, 53552, 43104); only
millisecond figures moved. Those were restored, per the 2026-10-29 and
2026-11-01 precedent.

**The thirteenth differs substantively and is reported rather than reverted
quietly.** P083's `validate_approx_audit_output.txt` forces every `approx()`
comparison to a zero absolute tolerance and names the tests that then fail.
The **count** is stable at 3 of 518 across three independent runs, and the
headline claim — 0 assertions depend on the 1e-12 absolute default — is
stable. The **membership** is not: the gate's run named
`test_log_norm_is_translation_equivariant` where the build run named
`test_log_norm_is_positively_homogeneous`. Both are Hypothesis property tests,
and which one trips depends on which examples Hypothesis generates, since its
storage directory is a fresh temporary directory each run.

So the committed artifact names three specific tests of which the third is
run-dependent. That is a reproducibility defect in the audit's *reporting*,
not in the product's bounds. It was **not** fixed tonight, deliberately:
editing a product after its gate verdict would publish an artifact the gate
never saw. It is carried over with a fix named — derandomise that one audit
run and re-gate.
