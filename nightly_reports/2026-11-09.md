## The finding of this session

**The working-directory probe created the failure it reported, and only the
coordinator's independent run could see it.**

The build agent reported **0 non-zero exits in 44 runs** of
`probe_working_directories.py`. The coordinator's run found **1**:
`validate_examples.py` from the repository root, exit 1. The release gate runs
every `validation/*.py`, so that single exit **would have blocked P081.**

The cause was in the probe, not in the product's examples validation.
`validate_examples.py` unlinks each shared `screenshots/*.png` and regenerates
it, then asserts the figure exists and exceeds 10,000 bytes. The probe
dispatched all 44 script-directory pairs into a two-worker pool, so two copies
of that one script could overlap, and one would delete a figure the other was
about to measure.

This is the **sixth** occurrence in this mission of the class the build guide
names — *a check whose own execution can create the condition it tests is not a
check* — and the **second** in which the harness rather than the script is the
polluter, after release-gate check 2 writing `.ruff_cache` before check 6 reads
the tree, which cost P084 a night.

What makes it worth a section rather than a line: **every remedy the build
guide already carries would have passed it.** The script exits 0 run alone from
the directory the probe blames. Two copies started by hand did not collide
either. The window is the few milliseconds between one copy's `unlink` and the
other's `stat`, and only the probe's own four-runs-over-two-workers dispatch
gives it enough chances — roughly 1 in 44. An intermittent, self-inflicted
failure is invisible to any number of agreeing serial verifications, which is
the same structural lesson as P084's but reached from the opposite direction:
there, three verifications agreed because they shared an assumption; here, they
agree because they never create the condition at all.

**Fixed at cause, two defects:**

1. Each script's four directory runs are grouped onto one worker and run
   serially, while different scripts still run two at a time. The same 44 runs
   spread over the same two workers, so wall-clock cost is unchanged — 436.1 s
   before, **449.4 s and 442.6 s** after, the difference being noise on two
   cores.
2. The probe reported only the failing script's `stderr`. These scripts report
   failed checks on `stdout` and exit 1 with an empty `stderr`, so **the one
   real failure it has ever caught printed no detail at all**, and the
   diagnosis had to be rebuilt by hand. It now falls back to `stdout`.

Per the build guide the fixed probe was run **twice** from a clean tree: 0 of
44 and 0 of 14 both times, with byte-identical per-directory status tables. One
clean run would have been weak evidence against a 1-in-44 intermittent failure.
