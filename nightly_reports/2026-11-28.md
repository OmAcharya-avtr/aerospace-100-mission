### The exact failure

Command, as mandated by the task prompt:

    git -c credential.helper= -c credential.helper=osxkeychain \
        push origin HEAD:refs/heads/probe-1795838894

Output:

    fatal: could not read Username for 'https://github.com': terminal prompts disabled

The cleanup delete failed identically. `git ls-remote origin refs/heads/probe-1795838894`
returned nothing, confirming no ref was created, so there is nothing to clean up.

Note the symptom differs from last night while the cause does not. On 2026-11-27 git sent
an empty credential and GitHub answered `remote: Invalid username or token`; tonight git
did not get as far as the network and asked for a username instead. Both are the same
absent-credential condition presenting differently. No mechanism for the change in
symptom is asserted here, because none was measured.

### Root cause - measured tonight, not carried over

- `security find-internet-password -s github.com` → no entry (`SecKeychainSearchCopyNext: The specified item could not be found`)
- `git -c credential.helper=osxkeychain credential fill` with `protocol=https/host=github.com` → `fatal: could not read Username for 'https://github.com': Device not configured`
- The helper is still configured and installed: `credential.helper=osxkeychain` globally (local and system scopes empty), binary present at `/Library/Developer/CommandLineTools/usr/libexec/git-core/git-credential-osxkeychain`, mode `-rwxr-xr-x root:wheel`
- The login Keychain is **not locked**: `security show-keychain-info ~/Library/Keychains/login.keychain-db` → `no-timeout`. A locked keychain is ruled out as the cause.
- `gh`'s own token is present and is a **generic** password, service `gh:github.com`, account `OmAcharya-avtr`. This is why `gh auth status` succeeds while `git push` fails: the git osxkeychain helper looks for an **internet** password for host github.com, and that item is the one that is gone.

No token was read, displayed, copied, committed or logged at any point. Presence and item
metadata were probed; no value was ever requested or shown.

Whether the credential was revoked deliberately by the owner or evicted by macOS remains
**not determinable from this session**, and that is still one reason this session published
nothing beyond its report.
