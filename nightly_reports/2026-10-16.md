### What the gate caught that nothing else did

This is the gate earning its 38 minutes. Every one of these survived the build
agent's own testing, its self-report, and the coordinator's re-measurement —
because all three ran the scripts from the product root, and the gate does not.

**1. Three products, one defect class: `worked_example.py` resolves relative
paths against the current working directory.**

- P065 `hazardtrace.errors.AnalysisFormatError: no such file: examples/cases/p024_bdot_detumble.yaml`
- P066 `budgetroll.errors.DeclarationError: no such budget declaration: examples/cases/cubesat_power.yaml`
- P069 `FileNotFoundError: no such file: fixtures/space.json`

Confirmed by direct measurement on P066: the identical script exits **0** when
run from `products/P066/` and exits **1** when run from anywhere else. The
scripts pass a bare relative string to `load()` instead of resolving against
`Path(__file__).resolve().parent.parent`. Every other validation script in
these products anchors correctly; it is `worked_example.py` specifically, in
three products, which suggests a shared shape rather than three coincidences.

This is a **new defect class for the build guide**: a validation script must
run correctly from any working directory, because the gate does not run it from
the product root. It is also the reason a product can be "verified" by three
independent parties and still be broken — all three verified it the same way.

**2. P064's fixture guard is itself giving 22 false failures.**

`validation/validate_fixtures.py` reports `FAIL on disk GIT WOULD SKIP` for all
22 of its committed fixtures. Measured: those 22 files **are tracked**
(`git ls-files products/P064/fixtures` returns 22) and are **not ignored** —
plain `git check-ignore -v` on the fixture exits **1**, meaning no pattern
matches. The script gets the opposite answer because it passes **`--no-index`**,
which tells git to evaluate the path as though it were untracked, and then
cross-checks against `git ls-files --others --exclude-standard`, which by
definition **never lists a tracked file**. Both halves of the verdict are
therefore structurally unable to pass for a committed fixture.

The script that was written to guard against the P060 ignore-pattern defect has
the same shape of error as the defect: it tests something adjacent to what it
claims to test. P064 the product appears sound; P064's guard is not. The fix is
one flag and one cross-check, but it belongs to a session that can re-run the
gate afterwards, so it is recorded and not attempted here.

Related and already noted above: `git check-ignore` exits 0 on a **negation**
match too, and the script's own header documents that trap while its verdict
line still trips over the `!products/*/fixtures/**/junit.xml` negation at root
`.gitignore:60`.
