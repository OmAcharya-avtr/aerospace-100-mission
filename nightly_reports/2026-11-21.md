## Process defect found and fixed inside this session

The first commit of the night, `10192ea`, was made with `git commit -a` and
therefore **did not contain this report**: `-a` stages tracked modifications and
silently ignores untracked files, and `nightly_reports/2026-11-21.md` was new.
The push succeeded and the tree on `origin/main` looked correct, so nothing
failed loudly. It was caught by reading the commit's own `--stat` — two files,
44 insertions, where a report of 180 lines must appear.

Had it gone unnoticed, this night would have reproduced the exact v4 failure
mode in miniature: a session that reports success while its report exists only
in a container that is about to be reclaimed. Recorded here because a defect
caught by the author and left out of the record is still a defect.

**Lesson for the next session: after committing, check `git show --stat` and
`git status --porcelain` before calling the push done. `git commit -a` is not
`git add -A`.** A new file needs `git add`.
