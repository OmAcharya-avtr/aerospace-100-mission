## BLOCKER_1 — cwd-dependent validation scripts — FIXED AND VERIFIED

Reproduced before being fixed, in both directions:

| Product | from product root | from `/` |
|---|---|---|
| P065 | exit 0 | exit 1 |
| P066 | exit 0 | exit 1 |
| P069 | exit 0 | exit 1 |

Root cause confirmed by reading the gate rather than inferring it:
`check_scripts` in `scripts/release_gate.py` invokes each script with
`cwd=d`, where `d` is the script's **own directory** — `validation/`, not the
product root. The scripts passed bare relative paths (`examples/cases/*.yaml`,
`fixtures/space.json`) to their loaders.

The part worth keeping is why nothing caught it earlier. The build agent, the
agent's self-report and the coordinator's independent re-measurement all ran
these scripts from the product root. Three independent verifications agreed and
all three were wrong, because they shared an assumption rather than a method.
Agreement among verifications that share a setup is not corroboration.

Fix: `os.chdir(ROOT)` in each product's validation support module, with `ROOT`
anchored on `Path(__file__)`. One line per product; a no-op when the script is
already run from the product root, so no previously passing case changes
behaviour. Verified exit 0 from four working directories — `/`, `/tmp`, the
product root, and `validation/` — for all three products. Re-running the scripts
reproduced the committed outputs **byte-identically**, so the fix changed no
recorded number.

**P070 carried the same latent defect** (no anchoring, and probe paths named
absolutely) and was fixed in the same pass.

A sweep of every product found three more scripts that exit 1 when run from

## BLOCKER_2 — P064 fixture guard — FIXED AND VERIFIED WITH NEGATIVE CONTROLS

Measured before fixing: 29 checks, 22 failures, every one of the 22 wrong.

The predecessor attributed this to `--no-index`. Measurement says otherwise: the
sole cause is the **cross-check**. `git ls-files --others --exclude-standard`
lists untracked, non-ignored paths, so in a clean tree it returns 0 paths and
cannot list a committed fixture by construction. `--no-index` was a second,
milder problem — it asks git to treat a tracked path as untracked, which is the
wrong question for a committed fixture and the right one for the hypothetical
per-run artifacts the script also probes, several of which do not exist on disk.

Fix: `REQUIRED` entries now cross-check `git ls-files` — being tracked is what
actually guarantees a cold clone has the file — and use the plain
`check-ignore` form for tracked paths. `--no-index` is kept only for the
hypothetical artifacts. `MUST_BE_IGNORED` additionally asserts the path is not
tracked. Result: 29 checks, **0 failures**, exit 0.

A repaired check that passes proves nothing on its own, so it was tested against
injected defects:

| Negative control | Required | Observed |
|---|---|---|
| untracked-but-on-disk file listed as `REQUIRED` | FAIL | FAIL, 1 failure, exit 1 |
| tracked file listed as `MUST_BE_IGNORED` | FAIL | FAIL, 1 failure, exit 1 |
| unmodified baseline | PASS | PASS, exit 0 |

The first attempt at these controls copied the script outside its directory and
tracebacked on `ModuleNotFoundError`. It exited 1, which looked like the
expected failure and was not one. The controls were re-run inside the validation
directory before any of this was believed. Recording that because an exit code
that matches expectation for the wrong reason is the easiest way to certify a
broken check as working.

## A trap in committing after a gate run — found the hard way this session

The gate re-executes every validation script and every plotting script, so a gate
run leaves the working tree dirty: 75 files across P061–P070, including 24
regenerated screenshot PNGs whose byte sizes moved substantially
(`products/P061/screenshots/feasibility_slack.png` 174,553 → 217,273 bytes).

This session's third commit was first made with `git add -u` and swept all 75 in.
That was caught before it was pushed and amended out: `products/` is now verified
byte-identical to `fe01a6a`, the tree the gate actually evaluated.

It matters beyond tidiness. The drift is this container's matplotlib and numpy
against the build sessions' — not a change in any result — so committing it would
have replaced the build sessions' measured artifacts with a re-render carrying
nobody's measurement, and it would have meant the committed tree was no longer
the tree the gate verdict refers to.

**Rule for future sessions: after a gate run, never `git add -u`.** Name the files
the session intended to change, and verify `git diff --quiet <gated-sha> -- products/`
before committing a verdict.
